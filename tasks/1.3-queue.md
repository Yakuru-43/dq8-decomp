# Task 1.3: funcdb.py --queue writes build/queue.tsv

**Goal.** The work queue for the function factory, generated from
`build/funcdb.tsv`. Regenerating it must never lose a state someone set.

**Read only:** `tools/funcdb.py`, and `.claude/skills/match-function/SKILL.md`
steps 1, 8 and 9 (how the queue is used).

**Format.** `build/queue.tsv`: tab-separated, one header line:

| Column | Value |
|---|---|
| `state` | `todo`, `claimed`, `matched`, `stuck`, `needs-claude` |
| `since` | `YYYY-MM-DD`, the day `state` last changed |
| `binary`, `func`, `addr`, `size`, `blocker`, `tu` | copied from funcdb |

**Which rows.** One row per funcdb row whose `status` is not `matched`.

**Keeping states.** If `build/queue.tsv` already exists, read it first and
key it by `(binary, func)`:
- a function that is now `matched` in funcdb: drop its row;
- a `claimed` row whose `since` is more than 1 day old: back to `todo`, `since` = today;
- any other existing row: keep `state` and `since`;
- a function with no row yet: `todo`, `since` = today.

**Order** (the factory takes the first `todo`):
1. by translation unit: rows with a `tu` (strip a trailing `?`) come first,
   grouped by that name, groups ordered by their lowest address; rows with
   `tu` = `-` come last;
2. within a group, `blocker` = `none` first, then `jumptable`, `entry-inside`, `hilo`;
3. then `size` ascending, then `binary`, then `addr`.

**CLI.** `tools/funcdb.py --queue` rebuilds funcdb first, then writes the
queue and prints `queue: N rows (todo T, claimed C, matched M, stuck S, needs-claude X)`.
Use a temp file plus rename, so a crash never leaves half a queue.

**Commit.** `tools/funcdb.py` alone, through the gate:
`funcdb: --queue writes the work queue and keeps existing states`.

**Check (pass/fail).**
1. First run at `8b2491d`: 8046 rows, all `todo`. The first row has a `tu`
   other than `-` and blocker `none`, and the last rows have `tu` = `-`.
2. Edit by hand: set one row to `stuck` and another to `claimed` with
   `since` = `2026-10-01`. Rerun. The `stuck` row keeps its state and date,
   and the old `claimed` row is `todo` with today's date.
3. Within every `tu` group, sizes of the `none` rows never go down.
   Check with a short awk or Python one-liner, and say which in your log.
