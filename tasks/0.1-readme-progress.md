# Task 0.1: honest progress in tools/readme_progress.py

**Goal.** The README progress block counts only what a fresh clone of the
repo actually builds from C, and leads with code bytes.

**Why.** `stats()` in `tools/readme_progress.py` takes every `src/**/*.c*`
file on disk. That includes `src/*/asmfunc/` (git-ignored verbatim asm,
119 functions) and files that aren't committed yet, so the README said
30.8% when the repo held 29.8%.

**Steps.**
1. In `stats()`, count a src file as done only if
   - it is tracked: in `git ls-files src` (run it once, keep a set), and
   - no path component is `asmfunc`.
   Other files still contribute their `// range:` start as a function start
   (so sizes stay right) but count as not done.
2. Put the code-bytes bar first on each line and the function bar second,
   and make the column header say so. Keep the same bar style and markers.
3. Move the counting into a function both tools can import, e.g.
   `progress_stats(binary) -> (funcs_done, funcs_total, bytes_done, bytes_total)`
   in `tools/readme_progress.py`; task 0.2 uses it.
4. Run it; commit `tools/readme_progress.py` and `README.md` (a tools commit,
   no `src/` files), through the gate.

**Check.** At HEAD 880763b, with nothing uncommitted under `src/`, the
"ALL game code" line must read **151/2828 KB (5.3%)** and
**3531/11577 functions (30.5%)**. Per binary: SLES_539.74 3101/9595,
TITLE 12/49, SHOP 109/452, MENU 97/428, CASINO 53/309, BATTLE 159/744.
If later commits added functions, the totals grow by exactly the number of
new tracked files.
