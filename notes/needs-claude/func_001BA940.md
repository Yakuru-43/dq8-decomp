# func_001BA940 (SLES_539.74, 0x001BA940, 48 bytes) — pilot P04

```

sd     $ra, 0x0($sp)
jal    func_001A2160          /* the current object, as an integer */
 nop
lw     $t9, 0xC0($v0)
lw     $t9, 0xC4($t9)

ld     $ra, 0x0($sp)
```

Calls `obj->field_0xC0->field_0xC4(obj)` and returns 1. The C is obvious and
so is everything except **one scheduling decision**:

```
* +010  daddu  $a0, $v0, $zero     lw   $t9, 0xC0($v0)
* +014  lw     $v0, 0xC0($v0)      lw   $t9, 0xC4($t9)
* +018  lw     $v0, 0xC4($v0)      jalr $t9
* +01C  jalr   $v0                  daddu $a0, $v0, $zero
* +020  nop                         ld   $ra, 0x0($sp)
```

Mine sets up `$a0` before the loads, so `$v0` dies and gets reused for the
call target; the original keeps `$v0` live for the argument, loads the target
into `$t9`, and puts the argument move in the `jalr` delay slot. That costs me
one `nop`: 52 bytes against 48. (`$t9` is the normal CodeWarrior target —
998 of the 1183 `jalr` in the main binary use it, 81 use `$v0`.)

Best C (and nine variations that all produced the identical output):

```c
extern u32 func_001A2160(void);

s32 func_001BA940(void) {
    u32 obj = func_001A2160();
    ((s32 (*)(u32)) * (u32 *)(*(u32 *)(obj + 0xC0) + 0xC4))(obj);
    return 1;
}
```

Tried: a `s32 (*handler)(u32)` variable then `handler(obj)`; a `struct Obj {
char pad[0xC0]; struct Vtbl *vtbl; }` with `obj->vtbl->fn(obj)`; a K&R
`typedef s32 (*Handler)();`; keeping the call result in a local; splitting the
two loads into named locals; `(u32)0` casts; `-O2` and `-O4` (both keep the
same `+0x10` difference).

Permuter not used: score 10, pilot rule 8 wants ≤ 5.

**What would fix it:** the idiom that makes mwcc hold the argument in the
`jalr` delay slot instead of hoisting it — probably something about the
callee's declared type, or a call the scheduler cannot move. Once known it
belongs in the skill: 998 call sites in this binary are indirect.
