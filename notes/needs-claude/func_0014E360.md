## What it seems to do

Buffer/heap allocator. `buf` fields: 0x18 list head, 0x28 alloc end, 0x34 tail gap,
0x38 cur node (matches func_0014E320, which finalises 0x38 and zeroes 0x28/0x34/0x2C,
and func_0014E500, the free side). Nodes: +0 next, +4 prev, +8 size (in 16-byte
units), +0xC size2. Walks the list from buf->18 while next != 0; per node:
`end = node + node->8*16`, `gap = (next - end)/16`; mode 1 takes the first gap >= 2,
mode 2 keeps the largest gap (best), mode 3 the first gap > limit (`min + size/16`),
each setting found=end, found_node=node. Then if found: insert new node after
found_node (doubly-linked), align `end = found+16` up to a multiple of
`units<<4` (units = size/16, divu/mfhi), store `found->0xC` and `*(end-4)` =
(end-found)/16, `found->8` = (end-buf->38)/16, buf->28 = end,
buf->34 = (found->next - end)/16. Returns end (or 0 on failure). Callers pass
(ptr, 2, 0, 0x40).

## What worked / signs confirmed

- Every `/16` is a signed divide (CW bgez + sra/addiu+sra form), incl. the entry
  `units = size / 16`.
- `sltu`/`sltiu` in the three mode tests and `(u32)end >> 4` `srl` + `divu`: model
  gap/best/limit/remainder as **u32** locals, keep the divisions signed
