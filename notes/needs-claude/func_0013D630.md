# func_0013D630 — inline VU0 (edge sub / cross / dot), same block as func_0013BFF0

`lqc2`/`vsub.xyzw`/`sqc2` (6x) + `vmul.xyz`/`vaddy`/`vaddz`/`qmfc2.ni` (3x),
the exact pattern proven not C-expressible this session in
notes/needs-claude/func_0013BFF0.md (CLASS structural, score=165). Pure-C

**Size:** 0x1A0 (416 B, 0x13D630–0x13D7D0). Binary SLES_539.74, own TU file
`game_13D630.s`.

**What it does:** oriented-box separating-axis test. Args `a0..a3` = four
vec4 corners, `t0` (→ `$s0`) = vec4 half-extents. Builds six edge vectors
`c[i]-c[j]` on the stack (VU0 `lqc2`/`vsub.xyzw`/`sqc2`, stack slots
0x90/0x80/0x70/0x60/0x50/0x40), three `jal func_0010ABC0` (cross product —
CPU-register args a0/a1/a2 = stack vec4 pointers), then three VU0 dot
products of the crosses with `*($s0)` producing floats in `$f3/$f2/$f1`.
Result: `r = 1` if all three are `< 0` (c.lt.s chain), else `r = 1` if all
three are `<= 0` (c.le.s chain at .L0013D77C), else 0; returns in `$v0`
(the `addiu $v0, $zero, 0x1` sits in `b`'s delay slot; single stub shared —
the "one return stub means nested ifs" idiom shape on the C side).

**Why needs-claude:** same as the 0x13B9xx family — mwccps2 has no intrinsics
for the VU0 chunks; the `addiu $v0, $sp, 0x..` register assignments feeding
`lqc2 0x0($v0)` are compiler-chosen registers no inline-asm can bind.
Suggested: asmfunc `asm void` stub like the 0x27DFxx family.

**Tried:** none (skipped per precedent). CPU-side half (c.lt.s/c.le.s chains,
delay-slot `addiu`, shared return) is plain C and documented above for whoever
stitches the asm stub.
