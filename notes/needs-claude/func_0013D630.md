# func_0013D630 — inline VU0 (edge sub / cross / dot), same block as func_0013BFF0

CLASS n/a by precedent — not attempted in C: the body is inline
`lqc2`/`vsub.xyzw`/`sqc2` (6x) + `vmul.xyz`/`vaddy`/`vaddz`/`qmfc2.ni` (3x),
the exact pattern proven not C-expressible this session in
notes/needs-claude/func_0013BFF0.md (CLASS structural, score=165). Pure-C
spelling cannot emit COP2 words; see also func_0013B900.md, func_0027E050.md.

**Size:** 0x1A0 (416 B, 0x13D630–0x13D7D0). Binary SLES_539.74, own TU file
`game_13D630.s`.

**What it does:** oriented-box separating-axis test. Args `a0..a3` = four
vec4 corners, `t0` (→ `$s0`) = vec4 half-extents. Builds six edge vectors
`c[i]-c[j]` on the stack (VU0 `lqc2`/`vsub.xyzw`/`sqc2`, stack slots
0x90/0x80/0x70/0x60/0x50/0x40), three `jal func_0010ABC0` (cross product —
CPU-register args a0/a1/a2 = stack vec4 pointers), then three VU0 dot
products of the crosses with `*($s0)` producing floats in `$f3/$f2/$f1`.
Result: `r = 1` if all three are `< 0` (c.lt.s chain), else `r = 1` if all
three are `<= 0` (c.le.s chain at .L0013D77C), else 0; returns in `$v0`
(the `addiu $v0, $zero, 0x1` sits in `b`'s delay slot; single stub shared —
the "one return stub means nested ifs" idiom shape on the C side).

**Why needs-claude:** same as the 0x13B9xx family — mwccps2 has no intrinsics
for the VU0 chunks; the `addiu $v0, $sp, 0x..` register assignments feeding
`lqc2 0x0($v0)` are compiler-chosen registers no inline-asm can bind.
Suggested: asmfunc `asm void` stub like the 0x27DFxx family.

**Tried:** none (skipped per precedent). CPU-side half (c.lt.s/c.le.s chains,
delay-slot `addiu`, shared return) is plain C and documented above for whoever
stitches the asm stub.

## Opus attempt 2026-11-03

**Byte-exact (`tools/verify.py` MATCH, 404 B), but the lint refuses it:**
`lint_contrived.py` rule `inline-asm` ("the bytes must come from C") rejects
any `__asm__`, and the rules say not to add `// permuter-artifact`. Not
committed. The user needs to decide: allow GCC-style VU0 inline asm (with
`.set noreorder`) as a recognised idiom (e.g. a marker like `// vu0-inline`
in the lint, or shared VU0 inlines in an `include/` header), or keep this
family in asm.

What the original is: plain C at `-O3` with small **static inline** VU0
helpers, each one GCC-style `__asm__` block whose **first line is
`.set noreorder`**. That keeps each block whole while MWCC still schedules the
C around it (jal/b delay slots filled, `addiu vN, sp, ..` from the `"r"`
operand placed just before each block). What doesn't work:
- `__asm__` without `.set noreorder`, or a CodeWarrior `asm { lqc2 vf4, 0(a) }`
  block: at -O3 the VU0 instructions get interleaved by the scheduler
  (60 words differ, same size).
- `tools/try_match.py` defaults to **-O2**, which gives 428 B with *every* delay
  slot empty, so it looks as if any asm turns scheduling off. Pass `-- -O3`.
  The note above ("not C-expressible") came from that.
  (MH2 catalogue, "What can't come from C": the `__asm__ volatile` entry,
  "schedules it with the code around it unless it starts with `.set noreorder`".)
