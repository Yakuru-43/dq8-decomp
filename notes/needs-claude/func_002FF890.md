# func_002FF890 (SLES_539.74, 0x002FF890, 496 bytes) — factory-3

Draws three segments on an object: copies the global table `D_003ACFE0`
(12 s32 = 3 groups of 4, as `offs[0..5]` pairs) to a stack buffer, then per
group `k` (O = `offs[2k]`, P = `offs[2k+1]`):

1. `func_0013EBF0(obj, O.x, O.y)`            (vertex push; see matched `src/SLES_539.74/func_0013EBF0.c`)
2. `func_0013EF90(obj, X1, arg2, 0)`         X1 = `arg1` | `arg1 + 0x12` | `arg1 + arg3 - 0x12`
3. `func_0013EBF0(obj, O.x + P.x, O.y + P.y)`
4. `func_0013EF90(obj, X2, P.y + arg2, 0)`   X2 = `P.x + X1` | `X1 + (arg3 - 0x24)` | `P.x + X1`

Guarded by `if (obj == 0) return;`. The odd one is block 2: its `X2` is
`X1 + (arg3 - 0x24)` with **no** `P.x` term (asm `addu $s6, $v0, $s0` with
`$v0 = $s2 - 0x24`, `$s0 = $s4 + 0x12`), unlike blocks 1 and 3 which use
`P.x + X1`. Everything about the semantics is settled; the open problem is
purely CodeWarrior's saved-register allocation and scheduling.
