## The question

What C does CodeWarrior 3.0.1b151 `-O3` refuse to constant-fold, when the value
is a `u16` that the compiler itself materialises as `daddu $s3, $zero, $zero`
one instruction before testing it? Candidates I could not test in time: a `u16`
read of a field that an earlier guard already proved zero (load-after-guard
forwarding, which would explain a *folded load* with an *unfolded compare*), a
`const` C++ static that the folder substitutes late, or a value produced by a
pass that runs after folding. If it is load forwarding, the source reads the
same 16-bit thing twice and I have the wrong field.

## Retry 2026-10-21 (Claude, P22 retry) — 14 shapes, still no match

Two shapes survive the folder (all of Qwen's plain-u16 forms and everything
below still fold to 104 B):

1. **Register-union form** — `union TableId { s32 whole; u16 id; }` with
   `table.whole = 0; if (table.id != 0) { … func_0033E980(table.id); … }`
   (best C `build/retry_p22/l-union-hoist.c`, 284 B): the fold NEVER fires and
   the ops are exactly right — wide store of the constant then a truncating
   narrow load: `sw $zero,0x5C($sp)` + `lhu $v1,0x5C($sp); bnez`, and the call
   arg `lhu $a0,0x5C($sp)`. But the RA keeps the union in the frame. The
   original has it in **$s3**: raw value in the register, `andi …,0xFFFF` at
   each use (`andi $v1,$s3` test, `andi $a0,$s3` arg). Tried to promote it:
   `.cpp` (extern "C"), `register union`, `s64` wide member, store hoisted
   above the guards — all still `sw/lhu 0x5C($sp)`. In this compiler an
   aggregate local never gets a callee-saved register (matches P45-family
   "aggregates are memory-resident" behaviour).
2. **Guarded-field re-read** — `id = entry->f58;` right after
   `if (entry->f58 != 0) return;` (best C `build/retry_p22/d.c`, 288 B): test
   survives unfolded as `andi $s1,$v1,0xFFFF; bnez $s1` — CSE shares the
   guard's `lbu`, truncation happens ONCE at the def and the arg later copies
   the truncated register (`daddu $a0,$s1`). The original instead truncates at
   EACH use from a raw register whose def is a constant zero. Re-reading
   through a wider type (`u16` `lhu` at 0x58, second struct view, `(const u16 *)`
   cast) blocks CSE but keeps the `lhu` — the load is never replaced by 0
   (the byte after f58 is not provable, so the branch-fact does not forward to
   a wider read).

Also ruled out this session: `(u16)` casts of an `s32` local (folds), bitfield
struct `{ u16 id : 16; … }` (folds), `static inline` helper called with 0
(folds — the inliner constant-propagates INTO the caller after inlining).
Corpus scan: the `daddu $sN,$zero,$zero` -> `andi $x,$sN,0xFFFF` pattern occurs
EXACTLY once in all of asm/ — this function; no matched precedent to steal.
Permuter skipped: base would be the m2c draft (wrong arg counts, family record
zero on P15/P16) and reordering cannot change type choices or RA homes.

Stable s-reg rotation across ALL shapes (incl. `register`, .cpp, re-declared):

s2=handle, s3=id` — and mine copies ctx before owner, the original copies
owner (tested, ctx copy in its delay slot). Declaration-order swaps (P18
