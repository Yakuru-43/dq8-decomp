  {1F,23,27,2D,33,3C,40,44,4A,50, 62-65, 67-6A, 6B-6E, 70-73, 74-77,

Mine emits an inverted `bnel` + a separate `b;li` block + an extra stub, so

instructions.

## Key findings

- The twelve groups **must** be twelve separate `if` statements (one shared
  return-1 stub each). One `if` per run of constants gets range-folded by
  CW into `addiu v,-c ; sltiu $at,4 ; bnel` — the original never folds,
  even for 0x62..0x65.
- `u16 v1 = (u16)arg0;` is what keeps CW from folding the runs **and**
  pins the subject to `$v0` / constants to `$v1` (an `s32` local goes the
  other way: `andi $v1,$a0` + `beq $v1,$v0`, like matched `func_002FE690`).
- `(u16)` + tail written as `return (v1==0x58) || (v1==0x5A)` or
  `? :` flips the register allocation back and folds nothing; the
  `if () return 1; return (…);` form is the only one that keeps `$v0`.
- CW compiled that `if` as inverted `bnel`; the original has `beql` with
  the `li $v0,1` fused into the delay slot, i.e. the taken path goes
  straight to `jr $ra`. Could not find the source spelling that produces
  the beql fusion; permuter (`--run 300` from this C as base.c) never beat
  my draft.
