- **Size:** 144 bytes (0x251200–0x251290), `asm/SLES_539.74/game_250A00.s`, 37 words.
- **What it does:** initializes a buffer-like object (clears `+0x10/+0x14/+0x1C/+0x20`,
  sets `+0x18=1`, clears bytes `+0x19/+0x1A`), then the sema-guard pair
  `if (buf->+0xC > 0) WaitSema(...)` / clear `+0x24` / `if (buf->+0xC > 0) SignalSema(...)`.
  Same TU as func_00251020 (this file) and its family — the *pointer-spill* shape of the
  sema guard: `addiu $a1,$s0,0xC` scheduled between the `+0x14` and `+0x18` stores, the
  first `bgtz` spills it in its delay slot (`sw $a1,0x2C($sp)`), the join block reloads
  `lw $a0,0x2C($sp)` and both the second test (`lw $v1,0($a0)` + plain `blez` + nop,
  SignalSema **inline** after it, `lw $a0,0($a0)` in the jal delay slot) and the
  WaitSema delay load (`lw $a0,0($a1)`) read through the pointer. Frame `-0x30` with only
  `sd $ra,0x10` + `sq $s0,0` — no `$s1`.
- **The wall (same as func_00251020, see notes/needs-claude/func_00251020.md):** CW keeps
  the `&buf->sema` pointer in an `$s` register (`addiu $s0,$s1,0xC`, saves `$s1`) or
  folds it away to `lw $r,0xC($s0)` (frame `-0x20`, no spill, second test becomes
  `bgtzl` + out-of-line call) — never the caller-saved `a1` + packed stack slot at
  `0x2C(sp)` + reload-at-join of the original. func_0025B760 (matched) reaches the
  identical `lw $vN,0x3C($sp); lw $v0,0($vN); blez; nop; jal SignalSema; lw $a0,0($vN)`
  shape **with plain `ch->sema` accesses on a `volatile s32 sema` member**, because the
  inline helpers there create register pressure that forces the spill; here nothing
  pressures the allocator.
- **MH2 entries consulted** (mwcc-matching-mh2.md): "Stack slots and frame size" —
  spilled var gets a packed 4-byte slot, compiler temporary a 16-byte one (entry
  "A stack slot 12 bytes off"); "Another value spilled than in yours: change which value

  pointer is set matters" (assigning `sema = &buf->sema` between the `+0x14` and `+0x18`
  stores did move the `addiu` there, but CW still allocated `$s0`).
