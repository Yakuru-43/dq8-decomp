## What it does
`func_0029AC20(unit /*a0*/, group /*a1*/, u8 key /*a2*/)`:
1. `func_00292CB0(unit, group)` — args passed through untouched.
2. `idx = *(group->items + key + 7)` where `group->items` (field at 0x368) is a
   `u8 *` (the same 0x368 field `func_00292CD0.c` reads); `key` is masked
   `& 0xFF`.
3. bounds check `idx < 0 || idx >= 118` (0x76) →
   `func_00300CB0(0, &D_003CBEA0, 0x130C)` (assert helper, file+line —
   neighbours `func_0029A100.c` / `func_002912C0.c` use it identically),
   then `idx = 0` and **execution continues** into the dispatch.
4. dispatches through a **12-byte-stride pointer-to-member-function table**
   `D_003CAB80[idx]` and returns `result & 0xFF` (`u8` truncation of an `s32`).

## The key discovery
The `lui/addiu D_003CAB80 + sll,addu,sll(idx*12) + addu $t9` sequence and
`jal func_00100E60` are CodeWarrior's **pointer-to-member-function call**.
`func_00100E60` (asm/SLES_539.74/text_100E60.s) is the RTL thunk: it reads
`{this_adjust, voff, vbase_or_fn}` from `*($t9)`, adjusts `$a0`, dereferences
the vtable and jumps. The source form that reproduces it byte-exact is a PMF
call (`(unit->*D_003CAB80[idx])()`), `typedef s32 (Unit::*Handler)(void)`,
function returns `u8`. This is the **first PMF function in the project** — no
`->*` in src/ before this, and `func_0030D3B0` (game_30D3B0.s) has the same
thunk call shape, so a working link recipe unlocks that one too.

## Blocker
mwcc emits `jal __ptmf_scall` for the PMF call; the real link has
`-nostdlib` and no object/config defines `__ptmf_scall`. The thunk's asm
label is `func_00100E60`, so an alias `__ptmf_scall = 0x100E60;` in
`config/symbol_addrs_SLES_539.74.txt` (or the RTL provided as its own object)
is the natural fix — but the factory rule forbids staging
`config/symbol_addrs_*.txt`, so this needs Claude / the integration side.

## What was tried
1. PMF call with `Handler` returning `u8`: no `andi 0xFF` truncation, epilogue
   folded wrongly → Handler must return `s32`, function returns `u8`.
2. `idx = *(u8 *)(group->items + key + 7)` and `key + group->items`: kept
   `lw $v0`/`andi $v1` swapped vs original (score 3, then 2).
3. `u8 *items` field type instead of `s32` + cast: fixed the `addu $v0,$v0,$v1`
   operand order (score 2).
4. Separate `sel = key;` statement before the load: the u8→s32 conversion
   forces `andi` to allocate `$v0`, `lw` gets `$v1` → byte-exact except the
   four relocation words.
5. `verify.py`: LINK fails on `__ptmf_scall` (see Blocker).
   `try_match.py` masks the relocations and reports MATCH.
