## Two open problems

**(a) `sqc2 $vf0, N($s0)` for the 16-byte zero stores.** Spellings tried,
none gives it:
- `Blk.q = 0;` (union `Blk { u128 q; f32 f[4]; }` member) → `sq $zero, N($s0)`
  (same word count, wrong opcode — register-only-ish diff of 6 words);
- four `bl.f[i] = 0.0f;` per block → 4 × `sw $zero` each, no peephole merge
  to sqc2 (function grew to 376 B);
- `memset(&unit->vD0, 0, 16)` (extern declared) → `jal memset` with
  `daddu $a1,$zero,$zero; addiu $a2,$zero,0x10` — not inlined.
Needs an mwccps2 trick: maybe a `// flags:` variant (`-O4,p` not tried here),
a VU-visible zeroing builtin, or asmfunc.

**(b) The `$v0` = &D_003DD9B0 base for the float stores is rematerialized.**
CW emits `lui $v0,%hi / addiu %lo` before **every** float store (11 stores →
11 pairs = 22 extra words, everything after shifts). The original has ONE
`lui/addiu` pair (at +0x28/+0x2C, which also feeds the `sw $v0,0xC0($s0)`)
and reuses `$v0` across the slot-0x48 `jalr`. Tried: direct
`D_003DD9B0.fXX = ...` writes; a single `FloatTab *tab = &D_003DD9B0;` local
used for all stores; and `raw->table = tab;` with the stored member and the
base sharing one `FloatTab *` web so the store and the uses had one def. All
rematerialize. See mh2 catalogue (not consulted this session — time box),
entries on constant remat / "declare locals so they get an `$sX`" — but the
original keeps it in caller-saved `$v0` across a `jalr`, which no spelling
I found reproduced.
