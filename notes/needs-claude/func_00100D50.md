## What it is

Drains the callback list headed at `D_003E1D00` (0x3E1D00), popping the
head before each call, like an exit-callback list:

```
addiu $sp, $sp, -0x10
lui   $v1, %hi(D_003E1D00);  sd $ra, 0($sp);  lw $a2, %lo(D_003E1D00)($v1)
beqz  $a2, epilogue;  nop
loop: lw $v1, 0($a2)                 # v1 = node->next
      lui $v0, %hi(D_003E1D00)
      sw  $v1, %lo(D_003E1D00)($v0)  # head = node->next   (store BEFORE call)
      lw  $a0, 8($a2)                # node->arg
      lw  $v0, 4($a2)                # node->fn
      jalr $v0;  addiu $a1, $zero, -1
      lui $v1, %hi(D_003E1D00);  lw $a2, %lo(D_003E1D00)($v1)  # node = head
      bnez $a2, loop;  nop
epilogue: ld $ra, 0($sp); jr $ra; addiu $sp, $sp, 0x10; nop nops
```

Siblings in the same TU: `func_00100DB0` pushes onto this list
(`node->next = head; head = node`, returns `a0` via `daddu`),
`func_00100D30` is a `func_0012D4A8` wrapper. Node layout confirmed:
+0 next, +4 fn, +8 arg. `fn(arg, -1)` matches the `destroy(p, -1)` idiom
of the matched `func_00100480`.

## Where it stands

The `build/drafts/func_00100D50.c` shape — guard clause + do-while:

```c
CBNode *node = (CBNode *)D_003E1D00;
if (node == 0) { return; }
do {
    D_003E1D00 = (s32)node->next;
    node->fn(node->arg, -1);
    node = (CBNode *)D_003E1D00;
} while (node != 0);
```

reproduces the control flow exactly: top `beqz` to the shared epilogue,
store before the call, `a1 = -1` in the `jalr` delay slot, bottom reload +
plain `bnez` (a plain `while` loop gets rotated by CW into a bottom-test
loop with `bnel` — do-while prevents that).

The whole remaining diff is Wall 2 of the `func_00100CA0` note: the
`D_003E1D00` load/store come out gp-relative (1 insn) instead of the
original's `lui %hi` + `lw/sw %lo` pairs, which also shifts register
allocation (`node` in `$a2` vs my `$v1`) and the `lui`-before-`sd`
scheduling. Fix the addressing mode and `tools/permute.py` should close
the rest.
