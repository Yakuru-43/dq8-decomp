# func_00102750 — attach one-word handler table twice: CSE wall

- Size 32 B (0x102750–0x102770), text_102750.s.
- factory-1 (Qwen) session 2026-10-22: 7 attempts, ~20 min, not matched.

## What it is

```
lui   $v0, %hi(D_003DF220)
addiu $v0, $v0, %lo(D_003DF220)
sw    $v0, 0xC($a0)
lui   $v0, %hi(D_003DF220)
addiu $v0, $v0, %lo(D_003DF220)
sw    $v0, 0x10($a0)
jr    $ra
addiu $v0, $zero, 0x1     <- in the jr delay slot
```

`D_003DF220` (ctors.data.s) is one word containing `func_00100000`.
The function stores its address into the caller's object at +0xC and
+0x10 and returns 1. Same family as the matched `func_00100DE0`
(`func_00100DE0(table, end, a2, a3)` calls every entry in `[table, end)`,
then `func_00102770(a2, a3)`) and the needs-claude `func_00100450`, which
tail-calls `func_00100DE0(&D_003DD3F0, &D_003DD66C, &D_003DF220,
&D_003DF220)` — there the same symbol appears twice as two live
arguments. This is plausibly an iterator/range init: `begin = end = table`
(an empty range over the one-word table).

## The wall — mwccps2 CSEs the duplicate address, the original does not

Every straight-line shape folds the two `lui/addiu %hi/%lo(D_003DF220)`
pairs into one materialization (kept in `$v1`, both stores read it), and
`scheduler` hoists `addiu $v0, $zero, 1` to +0x04, ahead of the stores.
The original materializes the address a second time into `$v0` between
the stores and leaves the `1` in the delay slot. My build is 6 words,
the original 7 — a missing instruction pair, not a reorder.

## Attempts (all -O3, tools/try_match.py --show)

Diff every one of these produced (mine | orig):

```
* +000  lui  $v1, 0x0          lui  $v0, 0x3E
* +004  addiu $v0, $zero, 0x1  addiu $v0, $v0, -0xDE0
* +008  addiu $v1, $v1, 0x0    sw   $v0, 0xC($a0)
* +00C  sw   $v1, 0xC($a0)     lui  $v0, 0x3E

* +014  sw   $v1, 0x10($a0)    sw   $v0, 0x10($a0)
DIFF at +0x0 (24 bytes)
```

(The `lui $v1, 0x0` vs `lui $v0, 0x3E` address value is an unresolved
relocation per the skill — but the register and the missing second pair
are real byte diffs.)

1. `extern u32 D_003DF220` + two `&D_` stores — first draft came out
   gp-relative (`addiu $v1, $gp, 0x0`); fixed with
   `__attribute__((section(".data")))` like `func_0015FF20.c`. Then CSE.
2. `u32 *table = &D_003DF220;` for the first, bare `&D_003DF220` for the
   second — still one pair.
3. `static inline u32 *HandlerTable(void)` called twice (the skill's
   inline-helper idiom) — still one pair.
4. Two different field types, `void (*fn)(void)` vs `u32 *data`, with
   casts — still one pair.
5. `extern char D_003DF220[]` (array decay) + two casts — still one pair.
6. `for (i = 0; i < 2; i++) h->slots[i] = ...` hoping for full unroll —
   not unrolled at -O3; runtime loop with `bnez` back-edge, worse.
7. `.cpp` under `extern "C"` with the two typed members — identical.

`tools/permute.py` cannot run here: `FileNotFoundError: 'cpp'` — the host
has no C preprocessor on PATH (this session may not install packages).
The diff is exactly the register-allocation / rematerialization case the
permuter exists for, so if `cpp` is made available this is worth a
`permute.py func_00102750 --run 600` before hand-editing.
