## Where it is stuck

Everything matches except one root cause: CodeWarrior CSEs `obj + 0xC`
into a register (`addiu $s0, $s1, 0xC` hoisted above the dispatch, then
`lw/sw 0x0($s0)`), which also makes `obj` itself land in `$s1`. The
original never materializes that address: `obj` is `$s0` (set in the
delay slot of the first `beq`) and all five 0xC accesses are
base+disp `lw/sw 0xC($s0)`.

Downstream symptoms of that one cause (all currently `*`):
`lw $a0, 0x9C0($s1)` vs `($s0)`, `addiu $t1, $s1, 0x40`, the path-D
`daddu $a0, $s1/$s0`, `sh $zero` scheduling into the `bltz` delay slot,
`beql $v0, $zero` + `daddu $v0, $zero, $zero` vs `beqz` + `nop` for the
two `func_0012C6C0` result tests (so its return is pointer-typed but the
stub sharing still differs), and the B/C dispatch (`beql -> B, fall
through C` in the original; `bnel -> C, fall through B` in mine).

Prologue, stack layout (frame 0xC0; path buffer 0x30, locals 0xB4/0xB8/
0xBC in that order), the 2-bytes-per-iteration countdown copy loop, the
v0=1 reuse for the `beq` and the `func_0012C6C0` a0, the path-D store
pair and the shared `daddu $v0, $zero, $zero` / `addiu $v0, $zero, 0x1`
return stubs all match.

## What I tried

- `char *obj` + `M2C_FIELD(obj, s32 *, 0xC)`, `= ... + 1`, and `++`: all
  three forms produce the same hoisted `addiu $s0, $s1, 0xC`.
- Local declaration order fixed to get slots right: `filename[0x80]`
  first, then `local_bc, local_b8, local_b4` (CW allocates scalars in
  reverse declaration order, arrays at the bottom).
- `char *` return type for `func_0012C6C0` (pointer test),
  `for (i = 0x40; i > 0; i--)` for the copy, `extern char D_003A5430
  __attribute__((section(".data")))` (without the attribute CW emits
  `addiu $a2, $gp, %gp_rel(D_003A5430)` — out of gp range, original uses
  lui/addiu %hi/%lo).
- Not tried (time cut-off): a typed struct pointer (`s32 state` at 0xC)
  so member access stays base+disp — theory: the M2C_FIELD macro's
  explicit `(char *)(expr) + offset` add is what CW value-numbers, while
  a struct member would not be hoisted. Needs handling the mixed
  `char *` args to the externs (maybe declare them with matching struct
  pointer or void pointer params).
