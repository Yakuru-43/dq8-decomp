# func_0014C680 (0x0014C680, 144 bytes, SLES_539.74 / game_14C310)

Looks up a keyed record in an object's list, with two fixed-field fast paths.
`obj = *(u32 *)arg0;` if obj is 0 return 0. If `arg1 == 1` return
`*(s32 *)(obj + 0x20)`; if `arg1 == 2` return `*(s32 *)(obj + 0x28)`; else
walk the singly-linked list at `obj + 0x30` (count at `obj + 0x2C`): each
entry `{next@0, key@4, value@0xC}`, return `entry->value` where
`entry->key == arg1`, else 0.

Original shape (asm/SLES_539.74/game_14C310.s:286): `sltu $v1,$zero,$a0` +
`beql $v1,$zero,<ret0>; daddu $v0,$zero,$zero` at the top (the predicate in
`$v1` is **retested** by `beql $v1,$zero` at the head of both fast-path
blocks; `$v1` is only reloaded with the count in the default block), then the
chain `addiu $v0,$zero,1; beq $a1,$v0,<body1>; nop; addiu $v0,$zero,2;
beq $a1,$v0,<body2>; nop`, then the default (count guard + loop) **inline**,
then body1 (`lw $v0,0x20`), then body2 (`lw $v0,0x28`), then `jr $ra`.
`$a0` = loop counter (reuses the obj register), `$a2` = cursor, `$v1` = count.

## What matched how far

The switch draft (best.c) is 144/144 bytes with every word in place; only 4
words are wrong and they move as a pair: writing the cases `case 2:` then
`case 1:` gives the chain tests in order 1,2 but lays the **bodies** as
(0x28 block, 0x20 block); writing `case 1:` then `case 2:` puts the bodies
(0x20, 0x28) right but the chain tests come out 2,1. CW emits the compare
chain in reverse source order of the case labels and the bodies in source
order (notes/idioms.md switch entry), so a plain two-case switch cannot give
chain(1,2) **and** bodies(1,2).

```
* +010  addiu $v0,$zero,0x2    addiu $v0,$zero,0x1     <- chain order
* +070  lw    $v0,0x28($a0)    lw    $v0,0x20($a0)     <- body order (same flip)
```
