## The shapes the original has (mine differs)
1. `sq $zero, 0x10($sp)` at +0x08: 16-byte zero of the buffer before any use. All four
   floats are unconditionally written later, so this looks like CW's zeroing of a
   16-byte aggregate (u128/vector type? cf. SKILL.md "lq/sq" struct-copy idiom).
   `f32 buf[4] = {0,0,0,0}` gives an `sb` loop instead.
2. Slots 1/2 (0x08, 0x10): plain `bnez $v0, TRUE_outofline` (NOT `beql`) with
   `addiu $v1, $a0, 0x8` (base = **tag** address, not value address) in the delay slot,
   false path inline (`lwc1 $f0,4($v1); b END; cvt.s.w`), TRUE out of line
   (`lwc1 $f0,4($v1)`), `swc1` at END. Mine (direct member access) folds to
   `beql` + `lwc1 off($a0)` — no base register, inverted polarity.
3. Slot 0 and slot 5 (0x28) do NOT use a base register: `bnel` with `lwc1 $f0, 0x4($a0)`
   (resp. `lwc1 $f12, 0x2C($a0)`) in the delay slot. So slots 0/5 direct, 1/2/3/4 via
   `addiu` base pointing at the **tag** word (`lwc1/lw` of the value at `4($v1)`).
   Mixed access: tag is `lw off($a0)` direct, value via the base. A pointer to a
   tag+value struct (so the base is `&tag`) reproduced the base but changed the branch
   polarity (try #2).
4. Delay-slot pipelining: the NEXT slot's tag load (`lw $v1, 0x20($a0)`) sits in the
   `b` delay slot at the end of the float arm AND at the end of the int (false) arm.
   Mine emits these late/serially.
5. `addiu $v0,$zero,1` for the `== 1` test materializes right after the tag `lw`
   (`lw $v1,0x18($a0); addiu $v0,$zero,1; bne $v1,$v0,false`); mine folded it into
   the test differently (got `bnel` at first).
