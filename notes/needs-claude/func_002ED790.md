## What it is

A scenario/event **command interpreter**. Two args: `a0` = context `Ctx *`
(kept in `s5` all function), `a1` = u16 command stream (`s4`; null-check
exits: `beqz $a1` in the prologue delay-slot region). Locals: `s3` = slot
index (valid range `0..0x13`), `s2` = a second counter, `s1` = the current
opcode. It loops `op = *stream++` and dispatches; many handlers accumulate an
`int` into a 20-entry dword array `ctx->arr[0x1DD8][s3]` or read the stream
again for inline operands.

## Main loop shape

```c
while (1) {                                  // .L002ED7D8  (0xED7D8)
    op = *s4; s4 += 2;                       // addiu s4 in the beq delay slot
    if (op == 0xFF00 || op == 0xFF03 || op == 0xFF01) {
        ctx->f161C = -1;                     // .L002EDEA4, OUT OF LINE
        ctx->f1620 = -1;
    }                                        // then b back INTO the chain
    switch (op) { ... }                      // .L002ED800 beq-ori chain
}
```

The terminator group stores both −1s in an out-of-line block at +0x714 and
`b`s back into the middle of the switch chain (after the `0xFF00/03/01`
tests), so the same op is still dispatched (0xFF01 → its own handler).
This is the P31 "unfused `||` chain to an out-of-line block" wall.

## The wall that dominates the function

**Every** `func_002F7070` call (≈15 sites) is followed by the accumulate
epilogue, which mwcc emits **unfused and interleaved with the address
math** — the `s3` range test is duplicated four times per site and sunk into
the delay slots of the surrounding chain:

```
jal  func_002F7070
bltz $s3, .next          ; s3 < 0 test #1, 1st delay slot after jal
slti $at, $s3, 0x14      ; s3 < 20 test #1
beqz $at, .next
sll  $v1, $s3, 2 ; addu $v1,$s5,$v1 ; addiu $a0,$v1,0x1DD8 ; lw $v1,0x1DD8($v1)
bltz $s3, .next          ; test #2 — SAME test, again, after the load
addu $v1, $v0, $v1
slti $at, $s3, 0x14      ; test again
beqz $at, .next
b    .next
sw   $v1, 0x0($a0)       ; store in the b delay slot
```

Plain C `if (s3 >= 0 && s3 < 20) ctx->arr[s3] += r;` fuses to one
`sltu`/`bnez` pair or a `bltz+beqz` with the add in a delay slot — never this
duplication. It is the P31/P32 "one guard, four copies, loads in the delay
slots of the branches" family, here repeated at 15 sites ≈ 360 B of the
5020. Whatever shape produced it (a macro? `volatile`-free register pressure?
post-increment?) needs Claude's eye; nothing in the skill idioms reproduces
it. The same block also targets different loop heads at some sites
(`.L002EE1C4/.EE1D0/.EE260`) — the continuation point differs per handler,
which is another P14/P15-style placement constraint.

Secondary walls:
1. The terminator `||` chain + re-entry mid-chain (P31; also P02 fold risk).
2. The default ladder's range pairs — `slt`-pair ranges have folded on us
   before (P02/P37); each `else if (a <= op && op < b)` is a fold risk.
3. Two epilogue entries: `.L002EEAFC` (`ld ra`, then fall into `.L002EEB00`)
   for most exits, and one `b .L002EEB00` with `ld $ra,0x90($sp)` in its
   delay slot from the 0xFF00 handler's `return` — different nesting depth.
4. `beqz $a1` null-check exits before anything is set up (guard clause, P08),
   with the `sq $s0` store in its delay slot.
