## Analysis / hypotheses

- `+0x104`: the original CodeWarrior kept `$a1` across the
  `func_00469C20` call, i.e. it knew the callee's register writes. That is
  the mh2 "Arguments kept or reloaded across calls (static callees)" entry
  (`/home/user/qwen-runs/ref/mwcc-matching-mh2.md` line 2697): the callee is
  `static` and defined earlier in the same file. `func_00469C20` is
  0x469C20, right in this MENU unit (adjacent to func_00468E30/004691C0) —
  very likely the same source file as this function. mh2's own workaround:
  "put a static copy of the callee at the top of a scratch copy of the
  caller's file" — but a second function in the file is a verify.py/build
  question (one function per file convention; `func_00469C20` is already
  matched as its own file).
- `+0x038/0x40/0x44`: `handle = func_181420()` keeps a live s-register copy
  (delay-slot `daddu s1,v0`) and the two `func_203740` args read from
  different registers. Related mh2 entries: "The game keeps a separate copy
  of a value that yours folds away" (line 1317; the idioms-new
  func_0021C6B0 typed-copy fix was tried, see below) and "A global leaf
  sends the value to a saved register instead" (line 2724, static-callee
  section) — CW may have known `func_181420` is a leaf only via unit/IPA
  knowledge.
