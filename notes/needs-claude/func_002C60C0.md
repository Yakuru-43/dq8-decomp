# func_002C60C0 (SLES_539.74, 1808 bytes) — pilot P38 (Claude)

Camera setup: copies a 0xDC-byte CamParams into the camera object
(D_003E100C, +0xC0), builds a matrix from three rotation vectors, places
eye/at/left/right/probe vectors, then either snaps the probe to a target from
`func_0016DE50` or casts five probe rays around the eye (`func_001E69B0`).
Best C: `scratch/pilot/p38_draft.cpp` (C++), 1872 vs 1808 bytes, ~45 min.

Cracked:
- the struct copy: `s32; s32[10]; Float4 (aligned(16) on the member) x3;
  Vec[6]; s32 x6; f32` reproduces the original copy code exactly
  (word, 5-step 8-byte loop, three 4-float groups, 3-step `lq` pair loop);
- a vector type that copies with `lq` both alone and in arrays:
  `union Vec { u128 q; struct { f32 x, y, z, w; } v; }` (a 16-aligned struct
  of floats copies with `lwc1` when alone);
- rot210/220/230/pos240 are one `Vec mtx[4]` (otherwise the pos store is dead);
- `mode` is an `s32` parameter (an `s8` adds a sign extension);
- `adda.s/madd.s` is just `eye.y += 0.5f * height` (CodeWarrior emits the ACC
  pair itself);
- the 5-ray table (D_003AA540) and the offset (D_003AA590..9C) are local
  initialisers copied from .rodata; written as copies from the symbols until
  files can own .rodata.

in `$s7` and fits in s0–s7; mine needs `$fp` too (frame +0x10, all stack
offsets shift). Loop variables and the `done` flag land in different
