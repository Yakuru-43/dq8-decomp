# func_00300AE0 (SLES_539.74, 0x00300AE0, 288 bytes) — factory-3

Member of the same draw family as `func_002FF890` (this directory) and the
matched `func_002FFCC0`. Pushes a 2-vertex polyline segment pair onto an
object's draw queue via `func_0013EBF0` (vertex, matched
`src/SLES_539.74/func_0013EBF0.c`) and `func_0013EF90` (move-to).

**6 parameters.** All ten call sites in `game_2FFAB0.s` (e.g. 0x2FFFD0,
0x300060) set `$t0`/`$t1` immediately before the `jal` (e.g. `addiu $t0,
$zero, 0x12; daddu $t1, $t0, $zero`) — CodeWarrior PS2 passes the 5th/6th
int args in `$t0`/`$t1`, like the matched 5-arg `func_00242A50`. So the C
signature is `func(void *obj, s32 arg1, s32 arg2, s32 arg3, s32 arg4, s32
arg5)`.

## What it does (semantics fully settled)

1. `if (obj == 0) return;`
2. Copy the global table `D_003ACCE0` (160 bytes = 40 × {s16 x, s16 y}) to a
   stack buffer `offs` at `sp+0x80`: copy loop is `lh/lh/sh/sh` + 4-byte
   stride, counter `0x28` decrement, `bgtz` — same shape as `func_002FF890`'s
   copy loop which compiled byte-exact there.
3. `p = &offs[(arg1 & 0xFF) * 2];` then four **zero-extending** `lhu` reads
   `p[0].x, p[0].y, p[1].x, p[1].y` → `u16` locals; each is stored
   `sw` to frame slots `0x120(sp), 0x124(sp), 0x128(sp), 0x12C(sp)` —
   **the only loads ever issued for these slots; they are never re-read.**
4. Four adds, all before the first `jal`: `s1 = x1 + x0`, `s2 = y1 + y0`,
   `s6 = arg4 + arg2` (`addu $s6, $t0, $s4` — `$t0` read in place, NOT
   copied to a callee-saved reg in the prologue), `s0 = arg5 + arg3`.
5. Calls: `EBF0(obj, x0, y0)`, `EF90(obj, arg2, arg3, 0)`,
   `EBF0(obj, s1, s2)`, `EF90(obj, s6, s0, 0)`.

Saved regs: `s0 = arg5+arg3`, `s1 = x1+x0`, `s2 = y1+y0`, `s3 = arg3`,
`s4 = arg2`, `s5 = obj`, `s6 = arg4+arg2`, `ra` at 0x70. Frame 0x130.
`s0` is saved in the guard `beqz`'s delay slot.

## The remaining problem (CodeWarrior scheduling, like func_002FF890)

The original rotates the block that does the 4 loads + 4 frame `sw`'s to
AFTER the call body: copy loop ends with `b .L00300BA8` (the load/spill
block at 0x300BA8) whose tail is `b .L00300B4C` (the 4 adds + calls).
Single pass, not a loop. My build keeps that block inline ahead of the adds,
which (a) drops the 4 dead `sw` stores (frame 0x120 vs 0x130), (b) delays
the `arg4+arg2`/`arg5+arg3` adds until just before the 4th call after
copying `$t0`/`$t1` into `$s2`/`$s1` in the prologue (before the `beqz`!),
and (c) shifts the add temporaries to `s0/s6` instead of `s1/s2/s6/s0`.

## Best C (prologue, guard, copy loop byte-exact; diverges at the +0x2C
where mine hoists `$t0`/`$t1`; full `try_match` diff = 252/252 bytes flagged
from +0x0 because of the frame size, but blocks 1–3 are identical)

```c
#include "common.h"

void func_0013EBF0(void *, s32, s32);       /* extern */
void func_0013EF90(void *, s32, s32, s32);  /* extern */

struct Off { s16 x; s16 y; };
extern struct Off D_003ACCE0[40];

void func_00300AE0(void *obj, s32 arg1, s32 arg2, s32 arg3, s32 arg4, s32 arg5) {
    struct Off offs[40];
    struct Off *src;
    struct Off *dst;
    s32 i;
    u16 x0;
    u16 y0;
    u16 x1;
    u16 y1;
    s32 sumX;
    s32 sumY;
    s32 ex;
    s32 ey;

    if (obj == 0) {
        return;
    }
    src = D_003ACCE0;
    dst = offs;
    for (i = 0x28; i != 0; i--) {
        dst->x = src->x;
        dst->y = src->y;
        src = src + 1;
        dst = dst + 1;
    }
    dst = &offs[(arg1 & 0xFF) * 2];
    x0 = dst[0].x;
    y0 = dst[0].y;
    x1 = dst[1].x;
    y1 = dst[1].y;
    sumX = x1 + x0;
    sumY = y1 + y0;
    ex = arg4 + arg2;
    ey = arg5 + arg3;
    func_0013EBF0(obj, x0, y0);
    func_0013EF90(obj, arg2, arg3, 0);
    func_0013EBF0(obj, sumX, sumY);
    func_0013EF90(obj, ex, ey, 0);
}
```

1. `u32` locals for the four table reads → `lh` (sign-extend) instead of
   `lhu`. Rejected.
2. `u16` locals → `lhu` ✓, but the scheduling/allocation diffs above
   remain (frame 0x120, hoisted `$t0`/`$t1` copies, adds into `s0`/`s6`).

Suggested next step (not run — session clock): `tools/permute.py
func_00300AE0 --run 600` on variant 2; the diff is register allocation and
block rotation only. Note the four `sw`'s to 0x120–0x12C look like spill

in a way CodeWarrior cannot delete — careful, no contrived C) or reordering
