# func_004634C0 (SHOP, 0x004634C0, 512 bytes) — pilot P30

SHOP overlay, `asm/SHOP/text_463240.s` lines 199–341. A shop-menu state
machine over the global byte `D_003E19B0`: `== 0x64` → refresh path, `!= 0`
→ return 0, `== 0` → init path (379xxx/376xxx builder calls, sets
`D_003E19B0 = 0x64`). Returns 1/0.

**Best C compiles to a 508-byte object whose only differences from the
original are relocation-masked — try_match reports MATCH, `verify.py`
reports MISMATCH, and the word diff is one big cascade from block
placement.** In `build/attempts/func_004634C0.c`.

## What matches

Prologue, the `func_00181420` / `func_0045F0E0` chain (`sq $s0` in the first
jal's delay slot — P21 idiom, matched as written), both guard tests
(`beq` to the 0x64 handler + `beql` with `daddu $a0,$s2` in the delay slot),
the `bnel s3,zero` with the `lw $a0,0x20(s2)` taken-path load (P19/P21),
`bgtzl s0` with the `lb $a0` delay slot, every callee's argument setup
including the N32 5th arg in `t0` for `func_379760`, and the dual
epilogues (`b .L004636A4` + `ld $ra` delay slot for the return-0 paths vs
full epilogue for return-1).

## What doesn't

Block order. Original: `[tests][return-0 branch][main body +0x510..0x630]
[0x64 handler at +0x634][shared return-0 block +0x67C][return-1 tail]`.
All four C shapes I tried — `if/else`, `if(){guards} if(){main} handler`,
`A-first` and `main-first` orders — make mwcc place the `0x64` handler
immediately after the tests (+0x50), before the main body, cascading ~105
words of offsets. This is the same rule P14/P15/P25 hit and it is still
unwritten down: **when the CFG has several guard exits plus shared tails,
what decides which block mwcc keeps in fall-through position?**

One real type finding on the way: the `D_003E19B0`/`D_003E19A8`/`D_003E19AC`
bytes are read with `lb` (sign-extend) — declare them `s8`, not `u8`
(`lbu` vs `lb` is a 1-word diff the relocation mask hides; try_match's
MATCH is not the authority — verify.py caught it).

## Tooling found while working on this (kept)

- `config/symbol_addrs_SHOP.txt` gained `_gp = 0x3E7270;` (head, above the
  keep_funcs block, like SLES has) — without it `verify.py` cannot link
  any SHOP file that touches gp-relative data (`R_MIPS_GPREL16` truncated).
- Absolute overlay data (D_00415E98/D_00415EB8/D_004735A0/D_00473600)
  needs `__attribute__((section(".data")))` on the extern (P24 idiom) or
  the link fails; gp-relative ones are plain externs.
