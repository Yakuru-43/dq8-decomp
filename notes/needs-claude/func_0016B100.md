## What it does
`switch (arg1)` cases 1/2/3 (compare chain tests 3, 2, 1 — plain switch):
each case bounds-checks `arg2` (signed `arg2 < 0` → bltz; `arg2 >= count` →
slt+beqz on the count `lw`ed from `arg0+0x550` / `+0x3A44` / `+0x3860`), then
computes `&obj[off + arg2*stride]` (stride 0x40 / 0x3C / 0x3C; off 0x554 /
0x3A48 / 0x3864). Default gives NULL. Common tail:
`beql $v0,$zero,+2; daddu $v0,$zero,$zero` / `lw $v0,4($v0)` — matches my
`return entry != NULL ? *(s32 *)(entry + 4) : 0;` exactly.

## The problem: per-case break stubs
Original keeps a per-case break stub `b <tail>; nop` (`.L0016B150`, `.L0016B184`)
that BOTH arms reach: success falls into it, the out-of-line fail stub is
`b <that stub>; daddu $v0,$zero,$zero`. Case 3 (last) and default branch
straight to the tail. Mine (228 B, 8 short): CW threads the fail stubs
straight to the tail (`b tail; daddu v0=0`) and gives the success path a
private `b tail` with the final `addiu $v0,$v0,0x554` hoisted into its delay
slot, so the stub never exists:

```
* +04C  b      . + 4 + (0x18 << 2)     addiu  $v0, $v0, 0x554
* +050  addiu  $v0, $v0, 0x554         b      . + 4 + (0x19 << 2)
* +054  bltz   $a2, ...                nop
```
Everything else (test chain, guards, address arithmetic incl. the
`sll4/subu/sll2` *60 expansion, the tail) is instruction-identical, only the
block layout after each success path differs (+2 words/case x2 vs my fold).
