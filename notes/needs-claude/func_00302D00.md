## The remaining wall

Every instruction of the loop body and tail matches 1:1 (arg setup order,
`addiu s2,s4,0xC` in jal#1's delay slot, `swc1 f20,0(s2)` in the `bnez` delay
slot, `lui 0x4300` + `b` + `sw` tail) — **as long as the allocator picks the
same 7 callee-saved registers**. Mine only ever allocates 6 (frame 0x80): the
`i<<4` temp goes to `$v0`, and the numbering is permuted (mine: s0=elem/i,
s2/s3/s4=arg copies, s5=addr; original as listed above).

What decides "7 s-regs + this exact numbering" is not visible from the
surface: the original's offset temp is dead across every call, yet CodeWarrior
spills it to s3 anyway; and the arg copies take s6/s1/s0, not the three
lowest free regs.

## What was tried

1. Guard clause `if (type != 11) return;` → compiler inverts to `bne`; the
   original wants `if (type == 11) { whole body }` (fixed, branch shape OK).
2. Named `offset = i * 16` local (needed for the shared `sll`); `i` alone in
   a reg still left offset in v0.
3. `f32 *pw = &vec->w` after the load → sunk into the store, addr vanished
   (store went direct `0xC(s4)`). Defining `pw` **before** the load keeps the
   addr alive across both calls → `addiu s2,s4,0xC` delay-slot shape appeared.
4. Explicit `(char *)arg1 + offset` / `(char *)arg2 + offset` address
   expressions with `p1`/`vec` locals → same score, numbering shuffled only.
5. `arg3->w = 128.0f` (f32 store via lui/sw) matches directly.
