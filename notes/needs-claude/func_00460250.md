## What it does
Fills an 8-float scratch buffer with `func_0045FA60(buf, 8, 0, 0)`, clears a
gp-relative global pair (`sd $zero, %gp_rel(D_003E16A0)($gp)`, scheduled into
the `jal`'s delay slot — write the store *after* the call), then for each of
`count` entries: loads `buf[i]` (f32) and `ptrs[i]` (void *), clears a 16-byte
local param block, sets member 0 = the float (swc1) and members +4/+8 = 0,
calls `func_14A9B0(ptr, &param)` (2-arg here; other TUs declare 5 args — a2/a3
stay 0 from the prologue, f12 garbage). Returns void.

## What matched / what I tried
- `memset(&param, 0, 16)` is NOT inlined by b151 at -O3 or -O4 (becomes
  `jal memset` + s3/f20 saves). Hand-written
  `cursor = (char *)&param; if (cursor != 0) { u32 n = 16; do { *cursor = 0;
  n--; cursor++; } while (n != 0); }` reproduces the guard + byte loop — CW
  does not fold the always-true null test.
- `s32 n` → `bgtz` (idioms.md "Count-down loop closes with bnez... a u32
  counter": with `u32 n` it becomes `bnez` — that entry was confirmed here).
- Declaration order swap `f32 buf[8]; Param param;` fixed the 0x40/0x50 local
  offsets (idioms.md "Stack arrays/locals at each other's offsets: declare
  them in reverse").
- The `sd $zero, %gp_rel(D_003E16A0)($gp)` extern needs
  `extern s64 D_003E16A0 __attribute__((section(".sdata")));` (attribute AFTER
  the declarator; prefix form → "illegal name overloading") and the name in
  `config/symbol_addrs_CASINO_local.txt` (`D_003E16A0 = 0x003E16A0;`) — that
  config edit is refused in factory sessions; verify.py currently passes only
  because the gp_rel reloc is masked as unresolved.
- MH2 catalogue: consulted via idioms entries above; none matched the
  `$a0`-as-index / `$v1`-as-cursor cluster around the inline clear.
