## The two things I could not reproduce
1. The saved value crosses `jal func_13BCA0` in **$f0** (caller-saved):
   `lwc1 $f1,D_00479D14; lwc1 $f2,1.0f; mtc1 $zero,$f0; nop; adda.s $f0,$f1;
   jal func_13BCA0; madd.s $f12,$f3,$f2; ...; swc1 $f0,D_00479D14`.
   CW spills anything live across a call to $f20+ unless the register is
   callee-saved in its model or the callee is known to preserve it. `adda.s
   $f0,$f1` after `mtc1 $zero,$f0` = `f0 = 0.0f + cur` — CW does not fold
   float `+0.0f`, but it *did* keep it in $f0 across the call.
2. `madd.s $f12,$f3,$f2` in the jal delay slot: $f12's prior value is not set
   on **any** path in the function (entry; the preceding calls return in $v0).
   It looks like C `x + step * 1.0f` with `x` an uninitialized float local,
   or CW emitting an acc instruction. $f2 = 1.0f, $f3 = step. My
   `func_13BCA0(cur + step * 1.0f)` produced `add.s $f12,$f20,$f1` + f20
   spill instead (mine folded `step * 1.0f` away? diff shows `mul.s`/`add.s`
