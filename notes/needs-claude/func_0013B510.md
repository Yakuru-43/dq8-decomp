# func_0013B510 (0xA0 bytes, SLES_539.74)

Saturating f64 -> s32 conversion. Calls the frexp-style decomposer
`func_0013AA18(&d, &parts)` (asm in `asm/SLES_539.74/sdk_128868.s:21348`,
writes kind@0x0, sign@0x4, exp@0x8, mantissa@0x10 of a 0x18..0x20-byte
struct; kinds: 2 = zero, 4 = subnormal, 3 = inf/NaN, 0/1 = normal).
Then: kind==2 -> 0; kind<2 -> 0; sign!=0 -> 0; kind==4 -> -1; exp<0 -> 0;
exp>=32 -> -1; else `(s32)(mantissa >> (60 - exp))` (a `<< (exp-60)` else
path exists in the asm but is dead after the 32 bound).

## Blockers

1. **Frame layout.** Original: parts@sp+0x00, spilled f64 arg@sp+0x20,
   ra@sp+0x30, frame 0x40. Every draft I wrote allocates parts@sp+0x20,
   d@sp+0x18, ra@sp+0x0 (frame 0x40, 0x8-0x18 hole) - CW puts the
   address-taken struct above the param spill. Padding the struct to 0x20
   and taking `&parts` before `&d` changed nothing. All 41 differing words
   follow mostly from the base offsets + the branch forms below.
2. **Branch form.** Original uses plain `xori+beqz`, `sltiu+bnez`, `bltz`,
   `beqz` with the *next* test's compute in each delay slot (e.g.
   `beqz $v1,.L5A4 / sltiu $a1,$a0,2`), and the `ld $ra,0x30(sp)` sits in
   the `bnez` delay slot. My -O3 build emits `beql/bnel/bltzl` with empty
   delay slots and duplicated `v0` materialisation (li+beql for ==2/==4),
   172 vs 160 bytes. Guard-clause style (idioms file) did not change this.
   kind is loaded once (`lw $a0,0($sp)`) and reused for all three ==/<
   tests; my build reloads via a computed `lw $a0,0($v0)` for exp.
