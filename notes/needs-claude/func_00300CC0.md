# func_00300CC0 — 544 B, SLES_539.74, range 0x300CC0 0x300EE0

## What it does
Transfer-size budget check over a queue `list` = `{ s32 count; {s32 id; s32 num;} entries[4]; }`:

1. `total = 0`; zero 16 bytes at `sp+0x90` (`used[]`, guarded byte loop); for each entry:
   `ret = func_002B0830(&D_0042EA80, entries[i].id, &size[i])` (binary search in a u16
   table, writes the size out-param), `hdr[i] = ret + 0x1E`, `size[i] += 0xC`,
   `total += (ret + 0x1E) + size[i] * entries[i].num`.
2. Zero 16 bytes at `sp+0x80` (`skipped[]`). `j = 0`. While `total < 0x867`, scan
   entries round-robin: if `entries[j].num < 2` → `skipped[j]++`; else
   `entries[j].num--`, `used[j]--`, `total -= size[j]`. On wrap (`j >= count`):
   `j = 0`, and (via a counted loop with a loop-invariant `slt $at,$zero,$a0` test on
   `skipped[0]`, see asm +E24) if `0 < skipped[0]` pop the last entry:
   `count--`, `total -= size[count] + hdr[count]`, `used[count]--`.
3. `return arg1;`

## Remaining diff (try_match --show, -O3)
First real diff +0x18. Two issues, both register allocation:

1. **$s mapping shifted.** Mine: `list=s5, arg1=s6, total=s4, i=s3, &size[i]=s2,
   &hdr[i]=s1, &items=s0`. Original: `list=s5, arg1=s4, total=s3, i=s2, &hdr[i]=s6,
   &size[i]=s1, &items=s0`. My `arg1` always spills to `$s6` before the saves finish
   (`daddu $s6, $a1` at +0x14); original copies it in at +0x24 into `$s4`, and the
   loop-1 temp `&hdr[i]` gets `$s6`. Everything then hangs one register off.
   Declaration-order permutations tried (arrays before/after scalars, `total`/`i`
   moved) never moved `arg1` off `$s6`. `tools/permute.py` was not run (time).
2. **Zeroing loops**: mine emits `bgtz $v0` for the countdown (CW proves `n > 0`);
   original has `bnez $v0`, and original hoists the `addiu $v0, $zero, 0x10` counter
   init to +0x04 (before the `sd $ra` save, i.e. before all saves); mine emits it
   after the `beqz` guard. `for (n = 16; n != 0; n--)` and do-while both give bgtz.
   `memset(&local,0,16)` is NOT a CW builtin here — it emits `jal memset`; the
   guarded inline-helper form reproduced the `beqz` + byte loop correctly.
