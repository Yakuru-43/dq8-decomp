## What blocks it

   `addiu $v1,$s1,0x40; ... bgtz; sw $v1,0x3C($sp)` then every early use is
   `lw $v1,0x3C($sp); lw $v0/$a0,0($v1)` (.L518/.L540/.L550 region). Mine keeps
   the pointer in `$s0` (frame -0x30) because `written`'s live range doesn't
   overlap it; everything after +0x18 is shifted 4 bytes → score 77. Note the
   later sema tests (.L570, .L59C) load `0x40($s1)` DIRECTLY, not via the stack
   pointer — so the source reads the handle two different ways in the two halves.

   Maybe `written` is live from entry (making $s0 taken and forcing the spill)
   but the materialized `daddu $s0,$zero,$zero` on the false path argues against
   a plain init-then-assign; try `bool written` defined via an early statement,
