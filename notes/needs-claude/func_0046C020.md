# func_0046C020 (MENU, 496 bytes, 0x46C020-0x46C210)

## What it does
Window/menu record builder. Gets a panel from `func_2D34C0` (early return if
null), zeroes a 0x408-byte string buffer at sp+0xD0, calls `func_374BB0(arg0, 2)`,
then `count = func_374B70(1)`. If count != 0: a `for (i = 0; i < 9; i++)` loop
calling `func_2D59A0(panel, 0x186F0, i, 1)`; when `arg1 + i < count` it fetches
`id = func_374B90(arg1 + i, 1)`, `item = func_3640B0(id)` (unconditional), and
when `id > 0` formats into sp+0x90 via `func_1340C0`, appends to the string
through printf-like `func_1339E0(cursor, D_00479448, buf)` advancing `cursor +=`
the return, reads pair values via `func_374740(arg0, id, &v4DC, &v4D8)`, then
`func_2D5FF0` / `func_2D59C0`. Else branch: `func_1339E0(cursor, func_1FFC30(0x28))`
(only 2 args!) and `func_2D38E0(panel, 0x186F0, 0, -1)`. Common tail:
`work = func_2D5410(panel, 0x522); if (work) func_221C20(work);`
`func_2D5440(panel, 0x522, str); func_2D4C30(panel, 0x186ED, count, arg1);`.
Stack: frame 0x4E0; saved regs 0x00-0x8F (ra@0x80); buf90[0x40]@0x90;
str[0x408]@0xD0; v4D8@0x4D8; v4DC@0x4DC.

## What differs (the remaining 70 words are mostly this one cause)
**Block layout.** Original block order is: loop, common tail (.L0046C0C8),
else block (.L0046C114, reached by `beqz $s2` + nop at +0x60, jumps back to the
tail), inner block (.L0046C148, reached by `slt $at` + `bnez $at` + nop, exits
via `b .L0046C0B8` with `i++` in the delay slot). Mine lays the inner block
right after the loop and the else last, uses `beql $s2` with `addiu $a0, 0x28`
hoisted into the delay slot, and `slt $v0` + `bnel` with `addiu $a1, 1` hoisted.
