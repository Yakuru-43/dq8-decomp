# func_002172B0 (0x2172B0, 688 bytes)

Sector-label generator: divides a world position by 16000.0f with a
round-to-nearest correction, then writes four 4-byte ASCII tags
`[letter,'0'/8,digit,0]` at `arg1 + 32*i` from a byte table `D_003DFD10`
(8 entries, pairs), and computes `arg2[0]/arg2[1]` as `(int)(i*16000*S) -
(int)(pos*S)` + constant, also folding the fractional part into two float
fields at `D_003E0908 + 0x460 / 0x464` (twin at `0x217130`, same tail).

Args: `a0` = 16-byte struct copy via `lq`/`sq` to `0x20($sp)`; the floats
read are words 0x20(sp) and 0x28(sp) (i.e. struct words 0 and 2 — the
`lq`/`sq` pair stores words (0,1) at 0x20 and (2,3) at 0x28). `a1` =
byte output base, `a2` = int* (two words), `a3` = flag for the `movz`
(0x180/0x200).

Constants: 0xFFFF2540 = -56000 and 0xFFFF63C0 = -39936 as **ints** fed
through `mtc1` + `cvt.s.w` (so the source likely adds int constants, not
float literals — try `(f32)56000`-style or a macro); `0x44FA0000` =
2000.0f (not 2008!), `0x467A0000` = 16000.0f, `0x45FA0000` = **8000.0f**
(not 8096), `0x43600000` = 224.0f; final
`mtc1 $v1; cvt.s.w` path converts the integer `half` to float.

Two odd words (only these two copies in the ROM, both in this function

Raw decode does **not** match standard `msub.s` (0x44831829-style): the
words are cop1, `rs`=10000b (cvt-family field), `funct`=0x1D, with
source reg in bits 10-6 — R5900-specific FP op; capstone mislabels it.

`f3 = (float)iy`, `f1 = (float)ix`, `f4 = 16000.0f`, so the true op is
probably `f? = f? - 16000.0f * f?` (extended-precision msub variant,
MADDx/MSUBx-like) and the two `c.lt.s` on `f1`/`f3` vs 8000.0f are the
rounding half-tests. The register roles do not fully resolve: the flag
that decrements `ix` comes from `c.lt.s $f1,$f0` and likewise for `iy`,
which is consistent with `if (x - 16000.0f*(f32)ix < 8000.0f) ix -= 1;`
but the dest of the two odd ops reads as `$f2` in the cvt-style field
layout (dead there) vs `$f3`/`$f1` in the disassembler's reading. Figure

compare the twin `func_00217130`.
