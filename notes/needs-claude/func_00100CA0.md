# func_00100CA0 — boot thunk: call fn ptr at D_0039CE18 (tail-call wall + gp-ref wall)

- Size 48 B (0x100CA0–0x100CD0), text_100970.s.
- factory-1 (Qwen) session 2026-10-22: ~4 attempts, not matched.

## What it is

```
addiu $sp, $sp, -0x10
lui   $v0, %hi(D_0039CE18)
sd    $ra, 0x0($sp)
lw    $v0, %lo(D_0039CE18)($v0)
jalr  $v0
nop
ld    $ra, 0x0($sp)
jr    $ra
addiu $sp, $sp, 0x10     <- in the jr delay slot
nop nop nop
```

A call-only thunk that loads a function pointer from the global
`D_0039CE18` (0x3ACE18) and calls it with whatever the caller left in
a0..a3; v0 passes through. Its only caller is `func_00101510` (0x101534),
which ignores v0. `func_00100CD0` and `func_00100D50`... see their notes:
same boot TU, same two walls, sibling `func_00100D00` duplicates `CD0`
exactly (both call `D_0039CE10`).

## Wall 1 — the documented tail-call wall

Same family as `func_00100780` / `func_00100860` (read those notes first):
at -O3 mwccps2 tail-call-eliminates every plain wrapper shape — here into
`lw $v0, 0($gp); jr $v0; nop` (12 B, no frame, no ra save).

## Wall 2 — scalar externs compile gp-relative, the original is absolute

Every attempt also produced `lw $v0, %gprel(D_0039CE18)($gp)` for the
pointer load, while the original uses a `lui %hi` + `lw %lo` absolute pair.
`func_0015F230` (matched, `extern s32 D_003E0298`) and the matched string
externs in `func_00100900` show both styles exist in the real objects —
what selects absolute is unknown. This wall also blocks `func_00100D50`
(`D_003E1D00`). Defining the global in the file is not an option: the
config format (`[addr, c, name]`) has no data-ownership mechanism for the
boot TU and `.bss`/`.data` additions show up as `DATA` in verify.

## Attempts (all -O3)

- `extern void (*D_0039CE18)(void);` + `void func(void){ ptr(); }` →
  tail jump + gp load.
- `extern int (*D_0039CE18)(void);` + void wrapper → identical.
- `extern int (*D_0039CE18)(void);` + `s32 func(void){ return ptr(); }`
  (the CD0 variant) → identical.
- The `func_00100860` note already ruled out K&R decls, struct-return and
  `asm("")` hints for this wall on direct calls; the indirect form behaves
  the same.

Best C: `build/drafts/func_00100CA0.c` (not in `src/`; config keeps
`[0x970, asm, text_100970]`).
