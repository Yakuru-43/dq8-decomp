## Size / what it does

76 bytes of code (0x102B30..0x102B7C, 80 in the queue incl. the 16-byte pad).
Constructor/initializer: `mgr(value)` sets, on `struct` at `$a0`:

- `0x20 (s32) = value` (first store)
- `0x3B (u8) = 0`
- `0x3A (u8) = (value == 0)` — the only hard part, see below
- `0x38 (u16) = 0x1002`
- `0x30..0x37 = 0` via one `sd $zero` (u64)
- `0x28..0x2F = 6` via one `sd $v1(6)` (u64)
- `0x04..0x1C` = 7 plain `sw $zero` (unrolled, NOT a rolled loop — a
  rolled `for` emits `sll/addu/slti/bnez` and misses)
- last `sw $zero, 0x1C($a0)` sits in the `jr $ra` delay slot

Offsets `0x00` and `0x24` are never touched (pad fields in the struct).

## The problem: the `value == 0` test

Original head (right column below):

```
  +000  sw          $a1, 0x20($a0)
  +004  addiu       $v1, $zero, 0x1
  +008  daddu       $a3, $zero, $zero
  +00C  sb          $zero, 0x3B($a0)
  +010  movz        $a3, $v1, $a1        <- full 64-bit $a1 tested
  +014  addiu       $a2, $zero, 0x1002
  +018  sb          $a3, 0x3A($a0)
  +01C  addiu       $v1, $zero, 0x6
  +020  sh          $a2, 0x38($a0)
  ... identical from here on ...
```

`addiu $v1,1; daddu $a3,0; movz $a3,$v1,$a1` computes `value == 0` from the
raw 64-bit `$a1` — a select on the register itself, no booleanizing compare.
Everything after +0x20 matched byte-for-byte in the best attempt; only these
9 head words are off (the branch form puts one extra word in and shifts).

## What was tried

   (booleanized, 2 words, orig has 3).
2. `value == 0 ? 1 : 0` → `xor; sltiu` (also booleanized). Explicit
   `sw zero`-per-slot instead of a `for` loop was required in both cases —

3. `empty = 0; if (value == 0) empty = 1;` (best, score 9) → branch, not movz.
4. `u64 value` param + `mgr->value = value; mgr->empty = value == 0;` →

5. `s64 empty; empty = value ? 0 : 1; mgr->empty = empty;` (s32 value) →

## Opus attempt 2026-10-26

Note first: `tools/try_match.py` defaults to **-O2**; pass `-- -O3` (Qwen's
scores above may be -O2 numbers). At -O3 the branch form scores 7.

**The `movz` comes from a ternary whose two arms are enum constants.**
mwccps2 3.0 booleanizes `c ? 0 : 1` with literal (or local/inline-propagated,
or cast) 0/1 into `sltu/xori`, but leaves `c ? ENUM_A : ENUM_B` as a select and
if-converts it to `movz`. Both arms must be enumerators (mixing one literal
in booleanizes again). Works in plain C, no C++ needed. (2.4-001213 keeps the
literal ternary as `movz`, but it uses `paddub` for moves, so the original
is a 3.0 build.) Best C, score 2, reorder-only:

```c
// range: 0x102B30 0x102B80
#include "common.h"

enum State { STATE_USED, STATE_EMPTY };

struct Manager {
    /* 0x00 */ u32 field_00;
    /* 0x04 */ s32 slots[7];
    /* 0x20 */ s32 value;
    /* 0x24 */ u32 pad_24;
    /* 0x28 */ u64 field_28;
    /* 0x30 */ u64 field_30;
    /* 0x38 */ u16 mode;
    /* 0x3A */ u8 empty;
    /* 0x3B */ u8 flag_3B;
};

void func_00102B30(struct Manager *mgr, s32 value) {
    mgr->value = value;
    mgr->flag_3B = 0;
    mgr->empty = value ? STATE_USED : STATE_EMPTY;
    mgr->mode = 0x1002;
    mgr->field_30 = 0;
    mgr->field_28 = 6;
    mgr->slots[0] = 0;
    /* ... slots[1..6] = 0 ... */
}
```

Remaining diff, words +4/+8 only: mine `daddu $a3,$zero,$zero; addiu $v1,$zero,1`,
orig `addiu $v1,$zero,1; daddu $a3,$zero,$zero`. Same registers, same
`movz $a3,$v1,$a1`; CW emits the then-arm (into the result reg) first, the
original emits the else-arm temp first.

Tried for that order, all still score 2 (same swap) or worse: `!value ? EMPTY : USED`,
