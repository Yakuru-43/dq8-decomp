## What it does
Downward allocator over a linked list of blocks `{ char *data; Blk *next;
s32 size16; s32 count; }` (next at +4, size in 16-byte units at +8, tail
count at +C). Starts at `pool->list1C->next` (arg0 + 0x1C). For each block:
`free16 = (blk->data - (blk + (size16 << 4))) / 16` (CW signed /16:
`bgez; sra 4` / `addiu 0xF; sra 4`), compare `(u32)free16 >= (u32)need` with
`sltu`/`beql` where `need = arg1 + arg2`. Found: `hdr = data - (need << 4)`,
`hdr->data = data; blk->data = hdr; hdr->next = blk; (Blk *)hdr->data
->next = hdr;` (the `lw a0,0(a1)` reload after `sw a1,0(a0)` comes free from
aliasing), `hdr->size16 = need`; then `end = (hdr + 0x10)` rounded up to a
multiple of `arg2 << 4` via `mfhi` (needs `-flag divbyzerocheck`: the asm
has the `bnez a2 / divu / break 0,7` guard); `hdr->count = (end - hdr) / 16`
(signed /16 again); `sw v1,0xC(a1); lw v1,0xC(a1); sw v1,-4(v0)` (the
reload triplet); returns `end` (0 if the list runs out).

   data in $v0, size16 in $v1. Fix (1) should fix (2).
