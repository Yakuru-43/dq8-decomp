prologue, identical through +0x48):

```c
void func_002FF300(struct Src *a, void *obj, struct Float4 *def,
                   s32 color, s32 arg4, s32 arg5)  /* $a0..$a3, $t0, $t1 */
```

- `a` (`$s5`): four `s32` at +0..0xC (clamped, see below), `s32 arr[4]` at
  +0x10 (used in the tail loop), `s32 mode` at +0x20 (passed to `func_002E2970`).
- `obj` (`$s4`): draw target; null-checked at entry AND again after the last
  `func_0013E2D0(obj, 0)` (second check's delay slot loads `c[2]`).
- `def`: copied to the stack with `lwc1`/`swc1` x4 at **sp+0xB0**; the
  fallback path re-reads it with `lw` as int bits.
- `color` (`$s3`): stored as the 4th byte of the prim struct, shifted
  `(color << 7) / 0x80` into `$t0` before the third `func_0013ECD0`, and
  passed as `$t0` to `func_002FF890` in the loop.
- `arg4` (`$t0`): only the 3rd arg of `func_002FFAD0`.
- `arg5` (`$s2`): dividend of the guarded `div` by a rematerialised 18.

Stack: four `s32` counters `c[4]` at sp+0xA0 (pointer passed to
`func_002FFAD0`/`func_002FFE10`), the float copy at 0xB0, a hole at 0xC0..0xC7,
a 4-byte prim `{0x80,0x80,0x80,(u8)color}` (+ callee-written tail?) at 0xC8.
The hole suggests the prim struct is 8-byte-aligned (s64/double member?) or a
different local sits at 0xC0.

Shape (all decoded, all four field guards): `v = a->x0; if (<0>) v = int-bits
of def->a; c[0] = v;` — the original guard tests use `slt $at, $v0, $zero` +
`bnez`, i.e. the constant-on-the-left form (`if (0 > v)` / `if (!(0 <= v))`),
where plain `v < 0` gave me `bltz` (diff +0x64).

Counters block (before the call all four are rewritten: c0+=2, c1+=2, c2-=4,
c3-=4, last store in the `jal` delay slot; then undone after: c0-=2, c1-=2,
c2+=4, c3+=4) — net zero, so the callees are expected to mutate `c` via the
pointer. After `func_002FFAD0(obj, c, arg4, c[1]_after_plus2)` the c values are
reloaded from the stack (they are call-clobbered), proving FFAD0 writes them.

`div` block: `q = arg5 / k; if (arg5 % k != 0) q++;` with `s32 k = 18;` — first
div carries the `bnez $v0 / break 0,7` guard (v0 = li 18, provably nonzero —
same unsolved construct as [[func_002FF0D0]]), second div (for the remainder)
is bare. `q` feeds `func_002FFE10(obj, c, q, prim)`.
