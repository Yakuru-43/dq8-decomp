## Opus attempt 2026-10-24

Three walls fall; 980 vs 984 bytes left, all register choice.

- **Div guard:** `// flags: -flag divbyzerocheck` (CodeWarrior's
  `#pragma divbyzerocheck`). The second `% 18` is unguarded because CW already
  checked that divisor; plain `arg5 / 18` would do too.
- **Stack layout:** locals are placed in reverse declaration order. Declaring
  `struct Prim p; struct Float4 d; s32 c[4];` puts c at 0xA0, d at 0xB0, p at
  0xC8 once `Prim` is 8 bytes (`u8 r, g, b, a; s32 unk4;`). The original stores
  the bytes b, g, r (0xCA, 0xC9, 0xC8) then a: assign in that order.
- **Guards:** the fallbacks are out-of-line blocks that do the store in their
  delay slot (`lw $v0, 0xB0($sp); b back; sw $v0, 0xA0($sp)`), i.e. both arms
  store: `if (0 <= a->x0) { c[0] = a->x0; } else { c[0] = bits(d.a); }`
  (`0 <=` gives the `slt $at` + `bnez` form).

Still different:
- Guard value registers: original alternates `$v0`/`$v1` per field (x0 v0, x1 v1,
  x2 v1, x3 v0) and keeps `&c[1]`, `&c[2]` in `$v0` temporaries, `&c[3]` in `$s1`;
  mine uses `$v0` for the values and `$s1`/`$s0` for `&c[1]`/`&c[2]`.
- After that the three element addresses are `$s0/$s6/$s7` in the original,
  `$s6/$s7/$fp` in mine, and the four draw coordinates are shuffled the same
  way. A shared `v` local or direct `a->xN` tests make no difference.
- One instruction short somewhere before +0x58 (branch offset 0xD2 vs 0xD3).

Best C: the `_best.c` with the three changes above (struct order, 8-byte
