## What it is
Virtual-dispatch thunk: tail-jumps to vtable slot 0x10 of the object in
`a0`, passing `a0` through unchanged. The dead `jr $ra; nop` epilogue means
the original was compiled as a call (ra-based) whose tail conversion kept
the epilogue.

wrong register, epilogue optimized away.

## What matches / what doesn't
- Plain C (any return type, statement-call vs `return`, array index vs
  struct member, callee void vs int): always `lw $v0`-chain + `jr $v0`, no
  epilogue. This CW build tail-calls indirect calls through the data reg.
- `.cpp`, plain fnptr member call: `addiu sp,-0x10; sd ra; lw $v0..;
  jalr $v0; ld ra; jr ra; addiu sp` — v0 AND non-tail. C++ never tails
  indirect calls here.
- `.cpp`, real `virtual` member (class with 3 virtuals so slot 0x10 lands
  right; tried int/void/pure-virtual, class inside/outside `extern "C"`):
  emits `lw $t9,0($a0); lw $t9,0x10($t9); jalr $t9` — **t9 and the slot
  match**, but always with `addiu sp,-0x10; sd $ra` frame and a real `jalr`
  (36 bytes). The vtable maps first-declared-virtual -> 0x8, so 3rd
  declared = 0x10 (no explicit dtor; adding one shifts slots).
- So the target = virtual call (t9) + tail conversion (jr, kept dead
  epilogue). This build never tail-converts a virtual call from any C shape
  I found. `permute.py` can't bridge jalr-vs-jr or synthesize the epilogue.
