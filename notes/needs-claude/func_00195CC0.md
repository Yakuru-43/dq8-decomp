# func_00195CC0 (SLES_539.74, 1264 bytes) — pilot P33 (Claude)

Per-frame tick of a link/communication state machine (D_0040FFA0 block:
host flag +1, pause +2, timer +4, ...; pending list at D_004102B0).
Best C: `scratch/pilot/func_00195CC0.cpp` (**C++**), **8 bytes short**: one
`sb $zero, D_004102B0` is missing; every other instruction matches.

Found on the way (these are new idioms, see the P02 note too):
- `x == 1` / `x > 0` computed into `$v0` (`xori`+`sltiu`, `slt`) and then
  branched on = C++ **`bool` compared with `false`**: inline
  `bool IsLinking() { return D_00410044 == 1; }` used as
  `if (IsLinking() != false)` / `== false`. In C, or with a plain `if (f())`,
  the compare folds into the branch.
- `slt $at, $s1, $zero` + `bnez $at` = **`if (0 <= ret)`** (constant on the
  left); `ret >= 0` gives `bltz`.
- One shared `b epilogue; move v0,s1` stub = the whole tail is nested ifs
  under `if (D_0040FFA1 == 0)` with a single `return ret;` (early returns
  give one stub each).
- The pending-list flush (`if (active) { for (i < count) func_001992C0(arg0,
  ids[i]); active = 0; }`) is an inline used twice.

The wall: at the second flush the caller stores `active = 0` again right after
the inline's own `active = 0`. CodeWarrior drops the first store as dead
unless the two stores look like different objects. A local `Pending *p =
&D_004102B0` keeps both but holds the address in a register (the original
reloads with `lui`); a `(u8 *)` cast on one store also keeps both. The
permuter matched in under a minute by routing the index and value of the
second store through a variable equal to 0, which is contrived. Not tried
yet: the flush as a member function of a `Pending` class (`this` pointer),
which may keep both stores without holding a register.
