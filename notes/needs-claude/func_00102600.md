# func_00102600 (SLES_539.74, 0x00102600, 100 bytes + 12 pad) — factory-1

Handwritten context-switch stub (`asm/SLES_539.74/text_102600.s` lines 10–42,
spimdisasm marks it "Handwritten function" and the delay-slot `sub` "handwritten
instruction"): restores s0–s7 (lq at 0x120…0x198), fp (lq at 0x200), f20–f31
(lwc1 at 0x288…0x2B4), the stack pointer (lw at 0x1C) and a bias (lw at 0x224)
from the context block in a0, then `jr $a2` with `sub $sp, $sp, $v0` in the
delay slot — it never returns. Its sibling `func_00102670` (same file) builds
such a block on its own stack frame (sq/sw of the same register set, saves
a0/a1/a2 at 0x0/0x4/0x8, ra at 0x10, sp at 0x14 and 0x1C, calls
func_00101060 with sp as a0), so this is the switch side of a coroutine /
saved-frame mechanism.

## Attempts

1. Tail call `void func_00102600(void *ctx, s32 a1, void (*target)(void))
   { target(); }` → `DIFF at +0x0: mine 00C00008 orig 78900120 (8 bytes)`:
   CodeWarrior keeps only `jr $a2; nop`. Every load is dead code in C
   (loads into callee-saved registers with no uses), so plain C can never
   emit them, and no C expression produces `jr $a2` mid-function with a
   `$sp` update in the delay slot.
2. Verbatim `asm void func_00102600(void) { … }` stub (the autodecomp
   `kind == "asm"` shape, house style from `src/*/asmfunc/func_0027DFE0.c`:
   no `$` sigils) → `tools/verify.py` says **MATCH** (100 bytes,
   3.0.1b151-050317 -O3). Not a legitimate match: it pastes the original
   instructions, and CLAUDE.md/`tools/gate.sh` keep `src/*/asmfunc/` out of
   the repo and out of progress anyway.

- The body loads s0–s7/fp (lq), f20–f31 (lwc1), `$sp` (lw 0x1C) from `a0`
  with no later use, then `jr $a2` / `sub $sp,$sp,$v0`. C cannot load

  matches the CodeWarrior runtime's saved-context frame, whose switch side

  `asmfunc/` is git-ignored, so the only matching form (the verbatim asm
