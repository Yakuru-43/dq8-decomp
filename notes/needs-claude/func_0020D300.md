## What it does

Second-half reset for the BGM object (same family as func_0020CC70 /
func_0020D110 / func_0020CF10):

1. `flag = (arg1 == 1)` (see wall 1 below for the shape).
2. The usual `0x5874` index ternary: `idx < 0 ? 0 : obj + idx*0xC0 +
   0x5610` (bgezl chain), then `func_00306170(slot)`,
   `func_0014DF10(slot+0x60, slot+0x40, 2)` and `func_00176500(*slot)` —
   byte-identical to the already-matched func_0020D0A0 body.
3. `for (i<2) func_00306170(obj + i*0xC0 + 0x5610)`.
4. `for (i<2)`: at `p = obj + i*6`: sh -1 @0x5868, sb 0 @0x586A/0x586B,
   sh 0 @0x586C (in the bnez delay slot — executes on both paths), then
   if flag: `func_00372CC0(obj + i*0x6C + 0x5790)` (0x6C chain
   sll3/add/sll2/subu/sll2, same as CC70's entry).
5. Straight-line stores then `func_0020D110(obj)`: 0x5610=0, 0x56D0=11,
   0x5874=0, s8@0x55F7=-1, s32@0x55F8=0xBF800000, u8@0x67E1=0,
   0x67E4=0, u8@0x55F4=0, s32@0x67F0=0 (call's delay slot — written
   before the call in the source, like D110's 0x64F0).

Counter is s0 in both loops (`slti 2` bottom test), flag s1, obj s2.

## The wall (two diffs vs the single 1-attempt draft)

1. **flag folding**: draft wrote `if (arg1 == 1) { flag = 1; } else {
   flag = 0; }` — CodeWarrior folded it to `xori $v0,$a1,0x1;
   sltiu $s1,$v0,0x1` (bool-ish). The original is the branch form:
   `addiu $v0,0x1` loaded in the prologue, `bne $a1,$v0,.+; daddiu
   $s1,0x1` / fallthrough `daddu $s1,$zero`. So something made CW keep
   the compare-to-1 branch; `flag` must not be treated as a bool value.
   Not tried yet: `int`-flavoured uses, or `flag = 0; if (arg1 == 1)
   flag = 1;` ordering, or comparing against a named const.
2. **&obj+0x5874 hoist**: draft gets a fourth saved reg (frame 0x50):
   CW CSEs `obj+0x5874` between the top `lw` (idx) and the tail
   `sw zero, 0x5874` and pins it into s0 (`addiu $s0,$s3,0x5874` before
   the bgez). The original loads/stores offset-form from s2 directly
   (3 s-regs). This is the same family as
   `notes/needs-claude/func_0020C5C0.md` / `func_0020C8C0.md` /
   `func_0020C240.md` (P22 wall): the session-6 CC70 trick (reuse the
   dead `slot` as a copy of obj, load via `*((s32 *)(slot + off))`)
   defeats the 0x64F4 variant and was NOT tried here. Also note the
   original's top `lw $v1,0x5874($s2)` is through s2 (obj) while the
   draft's went through $a0.

Everything else (both loops, the ternary, the tail store group, delay
slots) matched byte-for-byte in the diff — see try_match run:
