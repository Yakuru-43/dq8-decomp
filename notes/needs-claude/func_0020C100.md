# func_0020C100 — CW emits beql for the last equality test, C won't coax it

- Size: 128 bytes (`asm/SLES_539.74/game_20BFE0.s:99`), range `0x20C100 0x20C180`
- Queue: `SLES_539.74 func_0020C100`, tried 2026-10-21 by factory-2.

## What it does

Sibling of the already-matched `func_0020BF90` (same object, same index field
at `0x5874`): picks the `0x6C`-sized element at `obj + idx * 0x6C + 0x5790`
(a second array; the siblings use the `0xC0`/`0x5610` one), calls
`func_00372590(p)` and maps the result: `0→0, 2→2, 1→1`, anything else (and
the `idx < 0` / null-`p` paths) stays `-1`.

## The diff

Everything matches through `+060`. The last test is the whole problem:

```
* +064  bne   $v0, $v1, +2        beql  $v0, $v1, epilogue (+06C)
* +068  nop                       daddu $s0, $v1, $zero
* +06C  daddu $s0, $v1, $zero     daddu $v0, $s0, $zero   <- epilogue
```

The first two tests compile to `beql`-with-delay-slot-store from the same
draft; only the third — whose store is adjacent to the join — CW inverts to
`bne`/`nop`/store. All later stars are just the one-word shift.

## Tried

- plain `else if` chain (above) — best, 132 B.
- chain + `else { ret = -1; }` — CW rewrote the tail with `$a1` and dropped
  the s0 save area (120 B, prologue wrong).
- `switch (r)` with `case 0/2/1` — CW reordered and used `movz` (124 B).
- `else { if (r == 1) ... }` nesting — flattened, identical to chain.
- guard clauses (`if (p == 0) return ret;` + `ret = X; return ret;`) — CW
  constant-folded `return ret`, dropping the stores entirely (116 B). The
  single-return stub is required (skill: "one return stub means nested ifs").
- `1 == r` constant-on-left — no change (that idiom is for slt/bnez, not eq).
- `p` as `u32` — breaks the `p != 0` test: it must stay a pointer so
  `beqz`+`nop` (branch-not-likely) appears at `+03C`.
- `tools/permute.py func_0020C100 --run 600`: ~345k iterations, best score
  300, and the candidate is a comma-expression artifact — the `beql` shape is
  outside its mutation space. Do not take its output.

## Why it is hard

The two shapes at `+064` are semantically identical (equal → store then join;
not-equal → skip store, join). CW chose the nullifiable-branch form in the
original, which suggests the original CFG had an explicit jump out of the
last then-block (a `break`/`goto`/loop), or a CW heuristic tied to something
in this TU (see `func_0020BFE0`'s note — the neighbours here also defeat
naive drafts). `p` stays a pointer: `+03C` is `beqz`+`nop`.
