# func_00100860 — boot wrapper, tail-call/scheduling wall

- Size 32 B (0x100860–0x100880), text_100860.s, `nonmatching ... 0x1C`.
- factory-1 (Qwen) session 2026-10-21: ~8 attempts, not matched.

## What it is

```
addiu $sp, $sp, -0x10
sd    $ra, 0x0($sp)
jal   func_00100970
nop
ld    $ra, 0x0($sp)
jr    $ra
addiu $sp, $sp, 0x10        <- in the jr delay slot
nop
```

A call-only wrapper around `func_00100970(a0)` (boot loop: `func_00130400`
gate, `jalr D_0039CE00`, `func_00102670` on `D_003BEA10`, returns s32). The
wrapper passes no args (`a0` is whatever the caller left), sets no return
value.

## Wall

CodeWarrior refuses to emit this from any plain-C call shape:

- `-O3`, `extern void func_00100970(void);` + `void f(void){ g(); }` →
  tail call `j func_00100970` (also with K&R `()` decl and with `s32
  f(void){ return g(); }`).
- `-O2` fixes the frame (`addiu sp/-0x10`, `sd ra`, `jal`, `ld ra`) but the
  epilogue comes out `ld ra; addiu sp; jr ra; nop` — the `addiu $sp` must
  sit **in the `jr` delay slot** like every real function in this boot TU
  (`func_00100480`, `func_00100DE0`, `func_00100970` all do). Prototype
  void()/s32(), returning wrapper, K&R wrapper definition: all identical.

Permuter (`--run 240` from the plain wrapper): its ONLY score-0 output is
`do { func_00100970(); } while (*volatile_var * 0);` with a `volatile` local
— forbidden by `lint_contrived.py` (`while (0)` family + `volatile`). It is
a hint that the original call sat in a position that blocks tail-call
optimisation (a loop/non-tail context) which later optimised away to a
single `jal`. Natural C candidates that failed: `for(;;) { g(); break; }`-
style shapes, two-statement shapes, `s32 ret = g();` (all identical to the
plain wrapper).

Best C: `build/drafts/func_00100860.c` (`// flags: -O2`, K&R extern, void
wrapper; diffs only in the epilogue pair). Not in `src/`; config keeps
`[0x860, asm, text_100860]`.

Question for Claude: what natural source keeps `jal` + `sd/ld $ra` at -O3
while scheduling `addiu $sp` into the `jr` delay slot?

## Opus attempt 2026-10-24

`-O3 -opt tailcall,off` (the compiler's own switch; `-opt notailcall` is
silently ignored) keeps the frame and the `jal` from the plain
`void f(void) { func_00100970(); }`, but the epilogue comes out like `-O2`:
`ld $ra; addiu $sp; jr $ra; nop` (2 words differ). Adding `-opt schedule`,
`-opt peephole`, `-O4`, `-Os`, `-O3,p` changes nothing. So it is not just
tail calls being off; the rest of this boot TU (`text_1000xx`) may come from
another compiler or build. Worth checking whether any *matched* function in
`text_100000`..`text_102B30` exists at all before spending more here.
