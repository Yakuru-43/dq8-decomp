## What it does
Two guards, one byte load, two float returns:
- `arg0` guards: `bltz $a0,+nop` then `slti $at,$a0,0x10`/`beqz $at` → stub A.
- `arg1` guards: same shape vs 4 → stub B.
- `D_0042CDB8` (s32 in `.data`, same var as the getter `func_00342840`; the
  sibling `func_00327A70` casts its result to a struct) is loaded `lui/lw`,
  then `addu` `(arg0<<2)` (in `$v1`), `addu` `arg1`, `lbu` → `$v0`.
- `bltzl $v0,<neg>` with `srl $v1,$v0,1` in the delay slot — a signed `< 0`
  test of a `lbu` result (never true at runtime; CW kept it, do not let it
  fold).
- Positive (fall-through): `mtc1 $v0,$f0` / `b <join>` / `cvt.s.w $f0,$f0`.
- Negative `.L003427F4`: `andi $v0,$v0,1` / `or $v1,$v1,$v0` / `mtc1 $v1,$f0`
  / `nop` / `cvt.s.w` / `add.s $f0,$f0,$f0` → falls into join.
- Join: `b <jr>; nop`. Then stub A `mtc1 $zero,$f0; b <jr>; nop`, stub B
  `mtc1 $zero,$f0` (falls into `jr $ra; nop`), then padding nop.

So: `if (b < 0) f = (float)(s32)((b >> 1) | (b & 1)) doubled; else f = (float)b;`
