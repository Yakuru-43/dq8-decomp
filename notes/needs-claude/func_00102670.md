# func_00102670 (SLES_539.74, 0x00102670, 124 bytes + 4 pad) — factory-1

Suspend half of the coroutine / saved-frame mechanism whose resume half is
`func_00102600` (see its note here). Builds a 0x2C0-byte context block on its
own new stack frame: `paddub $v0, $sp, $zero` (pre-decrement sp), `addiu $sp,
-0x2C0`, `sq $s0..$s7` at 0x120…0x198, `sq $fp` at 0x200, `swc1 $f20..$f31`
at 0x288…0x2B4, then `sw $v0` at 0x14 and 0x1C, `sw $ra` at 0x10, the three
incoming args at 0x0/0x4/0x8 (the a2 store sits in the `jal` delay slot),
`paddub $a0, $sp, $zero` and `jal func_00101060` — and **no return**: the
function falls into the pad `nop`s, so `func_00101060` never returns
(scheduler side is `func_00101060`, 416 bytes, also needs-claude).

## Attempts

1. Plain C building the block in a large local array and calling
   `func_00101060(ctx)` → `DIFF at +0x0: mine 27BDFD30 orig 73A01628 (40
   bytes)` — differs across the whole 124 bytes. CodeWarrior emits only
   `addiu $sp,-0x2D0 / sd $ra / sw a0,a1,a2 / addiu $a0,$sp,0x10 / jal /
   ld $ra / jr $ra`. The original's prologue saves callee-saved registers
   ($s0–$s7, $fp, $f20–$f31) that are **dead in C** — nothing in the function
   reads them — so no C program makes CodeWarrior emit those stores; they are
   written for the *resumed* execution (`func_00102600` loads exactly them
   back). Nor can C capture `$ra` (`sw $ra, 0x10($sp)`) or the pre-decrement
   `$sp` into the block, or fall off the end of a non-noreturn-position
   without the tail return.
2. Same + `extern void func_00101060(void *) __attribute__((noreturn));` →
   identical diff; mwccps2 3.0.1b151 still emits `ld $ra / jr $ra / addiu
   $sp,0x2D0` at the tail.
