## What it does
`NumField *(NumField *field, s32 value)` — zeroes the object (u32 f00/f04/f08,
s16 f0C, u16 f0E), early-returns `f0E = 2` if `func_001294A0(field)` (called
with a0 = field, a0 never reassigned before the jal) or `f0E = 1` if
`func_001294E8(value)` (delay-slot `daddu a0, s1` — takes the value), then
`func_001339E0(buf@sp+0x30, D_003BEFC0, 0x1F, value)` (sprintf), assigns the
buffer into the string member via `func_00107040(field, buf)`, folds the digit
tail into `f0C` (`val*10 + (c - '0')`, `lh`/`sh` — an s16 read twice per iter),
negates it when `data[0x22] == '-'`, calls `func_00107B90(sp+0x78, field,
(s32)(data+0x22)-1, end)` and `func_00107C10(sp+0x70, field, data+1)`, then
converts `data[0..len)` in place from ASCII to digit values. Returns `field`.

## String model (shared with 6F80/6FF0/7040/7090 — matched? no, queued)
`flags&1` = heap: heap uses `{u32 len @4, u32 ptr @8}`; inline: `len = buf[0]
>> 1`, chars at `(u8*)this + 1`. Loop tests are inlined helpers recomputed
every iteration; `cur`/`end` are u32, compared with the `xor / sltiu 1 / xori 1
/ beqz` materialization (both sides need `dsll32/dsra32` materialization).
The digit loop starts at `data + 0x23` and compares against `data + len` — a
DEAD island for anything but `len == 0x23` (same dead-island family as
func_00106660): a straight `while (p != end)` compiles fine, but CW folded my
plain u32 `!=` into the branch and never emitted the xor/sltiu/xori triple.

## Wall
- Frame/locals: original frame 0x80, out params at sp+0x78 and sp+0x70 (8 B
  each, adjacent), buf at sp+0x30 (0x20 B); mine collapsed to 0x60 with the
  outs at 0x50/0x58 — cascade from +0xC0 onward. The 0x20-byte hole between
  buf (0x30–0x4F) and head (0x70) is unaccounted; maybe the outs are
  16-aligned structs or buf is 0x28 B.
- The inline length reads `lbu + dsll32 24 + dsrl32 25 + andi 0xFF` (a 64-bit
  truncate of `byte >> 1`); my `(u32)(*(u8 *)f >> 1)` gave `lbu + sra 1` —
  the length probably flows through an s64/u64 intermediate (member typed
  `u64`? a `(s64)` return?).
- `func_001294A0` is called with a0 = field (a0 still holds it from entry; the
  store block uses (a0) so a0 stays live); `daddu a0, s1` in the beql delay
  slot feeds func_001294E8.
- The second loop starts `cur = data` and reads `lw v0,0(s0)` for the test
  plus a separate `lbu v0,0(s0)` for the length, with `daddu v1, a0` (base
  precomputed as s0+1 BEFORE the length branch) — order of the inline helper
  expansion matters.
