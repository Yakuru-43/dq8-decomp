# func_00307C80

- Size 100 B (0x307C80..0x307CF0), binary SLES_539.74, asm `asm/SLES_539.74/game_307B10.s`.
- What it seems to do: bit-array test. Range-check `arg1 >= 0 && arg1 < 0x80`,
  then return `(((s32 *)((char *)arg0 + 0x350))[arg1 / 32] & (1 << (arg1 % 32))) != 0`.
  Bit array words start at offset 0x350 of `arg0`; 0x80 bits = 4 words.
  Sibling of the `func_00307B10` family (see `func_00307B10.md`), the flag-less
  twin — guards go straight to the shared `daddu $v0, $zero, $zero` stub.

## The problem: block order the scheduler refuses to emit

The value computation is right on every line; only the two blocks are swapped.
The original computes the **mask** (`1 << arg1 % 32`, bgez/andi/beqz/addiu/sllv
into `$v1`) first, then the **word index** (`arg1 / 32`, bgez/sra/addiu/sra,
`sll v0,2; addu v0,v0,a0; lw v0,0x350(v0)`), then `and $v0, $v1, $v0; sltu`.
CodeWarrior always schedules my loads first (see `func_00307B10.md` "register
facts": mask-before-word-index is a family property). Diff at best attempt:

```
* +014  bgez  $a1, +3        addiu  $v1, $zero, 1     <- orig: mask block here
* ...   (word index + lw)    ...
* +044  addiu $v1, $zero, 1  addu   $v0, $v0, $a0
* +048  sllv  $v1, $v1, $a2  lw     $v0, 0x350($v0)
  +04C  and   $v0, $v1, $v0  and    $v0, $v1, $v0     <- identical from here
```

Also note: in mine the shift value sits in `$a2`; the original keeps both
blocks in `$v0` scratch.

## Best C (score 14)

```c
s32 func_00307C80(void *arg0, s32 arg1) {
    s32 *words;
    s32 mask;

    if (arg1 < 0 || 0x80 <= arg1) {
        return 0;
    }
    mask = 1 << (arg1 % 32);
    words = (s32 *)((char *)arg0 + 0x350);
    return (s32)((words[arg1 / 32] & mask) != 0);
}
```
