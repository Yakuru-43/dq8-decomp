# func_00100450 — boot tail-call wrapper, arg CSE wall

- Size 48 B (0x100450–0x100480), text_100450.s, `nonmatching ... 0x24`.
- factory-1 (Qwen) session 2026-10-21: ~6 attempts, not matched.

## What it is

A tail call of the ctor-runner `func_00100DE0(start, end, a2, a3)`
(it calls every pointer in `[start, end)` then `func_00102770(a2, a3)`):

- `D_003DD3F0` = ctor table (`dlabel D_003DD3F0`, `.word func_003D6100 …`,
  ends at `D_003DD66C`), so this is `do_global_ctors`-style startup.
- `D_003DF220` = `.word func_00100000` (entry stub; neighbours `D_003DF224`
  = `.word 0x0045EC80` + zeros — a module/overlay descriptor).
- Original passes **the same address `&D_003DF220` twice**, but materialises
  it **twice**: `lui+addiu $a2, %lo(D_003DF220)` and `lui+addiu $a3,
  %lo(D_003DF220)`, then `j func_00100DE0` with the a3 `addiu` in the delay
  slot, then 3 pad nops.

```
lui a0,hi(D_003DD3F0); lui a1,hi(D_003DD66C); lui a2,hi(D_003DF220); lui a3,hi(D_003DF220)
addiu a0,lo; addiu a1,lo; addiu a2,lo; j func_00100DE0; addiu a3,lo(D_003DF220)
```

## Wall

Every plain C form lets mwccps2 -O3 CSE the two identical arg expressions
into one pair + `daddu $a3, $a2, $zero` in the delay slot (score 32/32 *).
Also reschedules a2 first. Tried (all emit the move):

- `func_00100DE0(D_003DD3F0, D_003DD66C, D_003DF220, D_003DF220)` (char[]
  externs, `char *` params)
- `..., D_003DF220, &D_003DF220[0])`
- `s32 desc = (s32)D_003DF220; ... D_003DF220, (char *)desc`
- `extern s32 D_003DF220;` with `&D_003DF220` twice

## Note

`func_00102750` (0x102750) duplicates `lui/addiu %lo(D_003DF220)` for two
stores too, so CodeWarrior CAN duplicate this symbol's address — the
question is what source shape prevents CSE across tail-call arg setup.
Prior session's draft had also faked a second operand as `&D_003DF224[-1]`
— contrived, do not use. Best C kept at `build/drafts/func_00100450.c`
(not in `src/`, not committed; `src/` and config keep it as asm).

## Opus attempt 2026-10-26

Solved in principle. It needs a user decision: a new symbol name in
`config/symbol_addrs_SLES_539.74.txt`, which this batch may not edit.

- **Two different symbols at one address.** a2/a3 are not one expression in
  the source. They are two linker symbols that resolve to the same address:
  the start and end of an empty region (`__xxx_start`/`__xxx_end`, start ==
  end). `func_00102750` stores the same pair at `+0xC`/`+0x10` of a struct.
  mwcc never CSEs two different symbols, and that explains both functions.
- **`-O4`, not `-O3`.** At `-O3` mwcc builds a stack frame and uses
  `jal`/`jr`, with no tail call. At `-O4` it schedules the four `lui`s first
  and puts the a3 `addiu` in the `j` delay slot, exactly like the original.
- Best C. try_match prints `MATCH (36 bytes, -O4)` with any second symbol
  name. verify.py gives `LINK` because the name is undefined:

```c
// range: 0x100450 0x100480
// flags: -O4
#include "common.h"
typedef void (*BootFn)(void);
extern BootFn D_003DD3F0[];
extern BootFn D_003DD66C[];
extern char D_003DF220[];      /* region start */
extern char D_003DF220_end[];  /* region end: needs `D_003DF220_end = 0x3DF220;` in symbol_addrs */
extern void func_00100DE0(BootFn *table, BootFn *end, char *a2, char *a3);
void func_00100450(void) {
    func_00100DE0(D_003DD3F0, D_003DD66C, D_003DF220, D_003DF220_end);
}
```
- To finish: add the alias to `config/symbol_addrs_SLES_539.74.txt` (the
  user's call), then verify. `func_00102750` should match the same way
  (two stores, `return 1`); it probably needs no `-O4` because it makes no call.
- Rejected: struct member `&D.entry` vs `&D` (still CSE'd, at -O3 and -O4),
  `(s32)` casts, separate locals, `-opt nocse` (no effect).
