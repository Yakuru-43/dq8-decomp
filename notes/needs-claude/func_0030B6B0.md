## PROVEN this session: the func_00100EA0 pmf idiom works

CodeWarrior **pointer-to-member-function designators**; `func_00100EA0`
(`asm/SLES_539.74/text_100E60.s`) is the compiler thunk that adjusts `$a1`
(the `this` register — CW PS2 passes `this` LAST, one user arg puts it in
a1), indexes, and jumps. Writing it as a C++ pointer-to-member call

  `func_00356910(arg0, func_0035DD40(v1, (a2 - 0xFB) & 0xFF));` —
  arg1 of `func_00356910` is `func_0035DD40`'s RETURN VALUE (the original's

  once nested.

## Open problems (the remaining 51-word diff)
1. **PMF register placement.** The thunk's `this` is `$a1` (adjusts a1),
   user arg in `$a0`: original before each `jal func_00100EA0` has
   `daddu $a0,$s0` only — `$a1` already holds arg1 (never clobbered since
   entry). CW instead emits `daddu $a0,$a1; daddu $a1,$s0` (this→a0,
   arg→a1, the normal member-call layout). Needs the declaration that
   makes CW pass the user arg in `$a0` and leave `this` in `$a1` —
   a virtual member with its single user arg, CW-PS2 "this last"? A
   non-virtual member pointer with the delta/base fields (drop `virtual`)?
   Try `(arg1->*D[idx])(arg0)` against a class without `virtual`, or
   multiple-inheritance upcast variants from idioms.md.
2. **Field-load registers.** Original: `lw $v1,0x158` then `lw $a2,0x15C`
   (a2 = 0x15C value, kept in `$a2` for every range test); mine allocates
   0x158→`$a2`, 0x15C→`$v1`. Probably follows from 1 (arg1's register
   pressure) — or swap the load/declaration order.
3. **Delay-slot CSE** (`beql a2<0xFA` with `addiu $v1,$a2,-0x12D` in its
   delay slot feeding only the branch-taken arm; fallthrough recomputes
   `a2-0xC9`): same trick that blocked `func_0030B5B0` (see its note) —
   unresolved. Mine currently emits the same two sub shapes, unverified.
4. With the register drift fixed, the NIL/epilogue block placement
   (`b .L7C8; ld ra` delay slot vs fall-in `.L7C4`) should follow.
