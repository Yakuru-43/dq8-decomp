## What it seems to do
Constructor-shaped function (sibling of the matched destructors
func_001034A0/func_00103500): `obj->4 = &D_003DD6F0` (vtable),
`*(u32 *)obj->0 = &D_003DD6FC`, `obj->0->0x48 = (char *)obj + 8 - obj->0`
(virtual-base delta), then when `n != 0` it sets `obj->8 = &D_003DD6D8`
and calls `func_00102A50(obj + 8, 0)` (sub-object constructor; its store
sits in the call's delay slot); `n > 0` (16-bit) frees `obj` via
func_001007A0. Returns `obj`. The `!= 0` test on `n` is on the raw
register (so `n` is an `s32` there) while the `> 0` test sign-extends
(`(s16)n > 0`) — plain `s16 n` makes CodeWarrior hoist a
`dsll32/dsra32` of `$a1` into `$s1` and diverges.

i.e. the original keeps `&D_003DD6F0` in `$v0` (stored at +0x4 while
`$v0` still holds it, then `$v0` reused for the `handle` load), while my
build keeps it in `$v1`. Rest of the function is byte-identical
(ignoring masked `lui/addiu` addresses and `jal func_000000`).

## What was tried
- m2c: no draft (build/repair empty for this func); permute.py unusable
  here — no m2c draft and no `cpp` binary on this host (`FileNotFoundError: cpp`).
- statement order of the two vtable stores (F0-first vs FC-first):
  F0-first gives the exact instruction order but the `$v0`/`$v1` mirror
  above; FC-first fixes the roles but hoists the `handle` load to +0x1C
  (into `$a1` or `$v1`) and swaps the two `sw`s.
- u32 `(char *)obj + N` casts vs a typed `struct Node` — the struct was
  required to get `sw $v0, 0x8($s1)` (with casts CodeWarrior reuses the
  live `$a0` register: `sw $v0, 0x0($a0)`).
- `subvtbl` local to precompute `&D_003DD6FC` — copy-propagated, no effect.
- `n` as `s16` param (hoists a sign-extend of `$a1`, breaks +0x20..+0x48).
- guard-clause split `if (n != 0) { sub = ...; if (sub != 0) {...} }`
  reproduces both `beqz`s (target L668) with the delay-slot store exactly.

Likely the original was a CodeWarrior **C++ constructor** (vptr stores

order. Reproducing the class layout (virtual base at +0x8 with delta at
handle+0x48) is beyond what I can reach from C.
