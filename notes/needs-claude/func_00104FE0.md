## The two walls
1. **Then-block placement.** CW always cold-places the `if (n == 0x10)` block
   (forward `beq` + block at the tail + `b` back), while the original has
   `bne a0,v1,skip` falling through it. Tried: `n == 0x10`, `0x10 == n`
   (constant-left idiom), inverted `if (n != 0x10) { } else { ... }` — all
   three produce identical bytes (388, 29). The cold block wedges between the
   `daddu v0,v1` return-1 stub and the epilogue, so the stub becomes
   `b + daddu-delay` (extra word) instead of the original's fall-through —
   this is the whole 388-vs-384 and most of the 28-word diff.
2. **g = u+0x23 vs eg-1.** `(u32)&buf_24[n + 1] - 1` keeps the shared `u` node
   but derives g from eg (constants 0x24/-0x1). Writing g as `&buf_24[n]`
   regresses badly (392, 32: n falls back to a1, g = `addu v1,s0,a1; addiu
   0x24`, eg via its own chain — no sharing). `&buf_24[(n + 1) - 1]` folds the
   index to `n` first (identical to `&buf_24[n]`). `&buf_24[n + 1] - 1`
   without the cast folds the same way. So CW must be coaxed to normalize g
   through the (n+1) node while keeping eg separate.
