## Why stuck (register-level, systematic)
1. **Saved regs swapped.** Original: `work`→$s0, `obj`→$s1, `n`→$s2 (mine: obj→$s0,
   work→$s1; every `$s0`/`$s1` in my dump is the other variable). Swapping declaration
   order (work first / obj first) and typing `work` `s32` vs `char *` did not change it.
2. **Compare register roles flipped everywhere.** Original loads the tested value into
   `$a0` and materializes the constant into `$v1` (`lh $a0,0xC($s1); addiu $v1,$zero,0x4B;
   beq $a0,$v1`; same for all three `tag == 3` tests: `lw $a0,8($s2); addiu $v1,$zero,3;
   beq $a0,$v1`), and the range test uses `$at` for `sltiu`. Mine always folds the value
   into `$v1` and the constant into `$v0`, with `$v0` as sltiu scratch. Possibly
   consequence of (1) (in mine `$v0` is free after the late `daddu $s1,$v0` copy; in the
   original `$v0` still holds work when the chain is built).
3. **then/else placement.** Original `beql $s0,$zero,<cold>` keeps the `work != 0` block
   inline and the work==0 block cold after the stubs; my `if (work != 0) {...} else {...}`
   gave `bnel` + then-block out-of-line, and `if (work == 0)...` gave the reverse.
4. Slot 1's link load is `addiu $a1,$s2,8` (beq delay slot) + `lw $v1,4($a1)` in BOTH
   paths (idioms.md "Unrolled {type, ptr} slot stores" — the pointer-local spelling
   `sl = n->pair + 1; if (sl->tag == 3) sl->link->value = v;` reproduced this), but slots
   0 and 2 stay folded (`4($s2)`, `0x14($s2)`).
