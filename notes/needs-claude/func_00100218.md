Tail-call thunk: `j func_00120F98; nop` (asm/SLES_539.74/text_100000.s
lines 162–165). The C below is **byte-exact** — `tools/try_match.py` says
MATCH (the only `*` is the masked `R_MIPS_26` on the `j`):

```c
// range: 0x100218 0x100220
#include "common.h"

void func_00120F98(void);                               /* extern */

void func_00100218(void) {
    func_00120F98();
}
```

(`func_00120F98` is a small wrapper in `sdk_118430.s`: `s0 = a0; jal
func_00120ED8; j Exit`.)

## The wall: verify's link pads in front of a non-16-aligned function

mwccps2 emits `.text` with `sh_addralign = 16`. This function sits at
0x100218 (8 mod 16), so `autodecomp.verify()`'s link (`ld -Ttext 0x100218 -T
build/<bin>_all_syms.ld`, no `SECTIONS` command → default script) honours the
16-byte alignment and inserts 8 bytes of zero before the section:

    map: .text 0x00100218 0x10,  .text 0x00100220 0x8 /tmp/f218.o
    linked .text: 00000000 00000000 e6830408 00000000   (mine)
    original:     e6830408 00000000                     → MISMATCH

The real build is not affected: `linker/SLES_539.74.ld` uses `SUBALIGN(4)`
for `.main`, which overrides input alignment — the bytes would land correctly.
Only verify is broken for non-16-aligned functions; `git log` shows every
committed match so far was 16-aligned, so nobody hit it. In this queue slice
exactly two rows are non-16-aligned: this one and `_start` (0x100008).

## What was tried

1. `void func_00100218(void) { func_00120F98(); }` → correct bytes (above),
   fails only the link padding.
2. No compiler-side escape: this mwccps2 has no `-align` option (`-help` has
   no 'align' at all) and rejects `__declspec(align(n))` (Error at `align`).
3. Making the bytes fill the padding is impossible: the pad is emitted by
   the linker *before* the section, not by the object.

## Fix for Claude (one line, in tools/autodecomp.py)

`verify()` should make the link ignore the input alignment, e.g. after
`set_abi.py` patch `.text`'s `sh_addralign` to 4 (an 8-byte struct write at
the section-header offset; autodecomp already parses ELF headers with
`struct`), or link with a tiny wrapper script
(`SECTIONS { .text SUBALIGN(4) : { *(.text) } }` merged into the symbol
assignments). Then this file matches as committed and `_start`'s row is the
only non-aligned one left (it is the handwritten entry — see
`notes/needs-claude/func_00100000.md`; both are queue noise that funcdb
could skip).
