The three blocks run 0x47C580 → 0x47C6A0 with no return or jump between them:
one function, entered at 0x47C580, that something also branches into at
0x47C5A0 and 0x47C5B0. No C compiles to a 32-byte prologue that does not
return, so the range as given cannot match.

**What would fix it:** decompile 0x47C580–0x47C6A0 as one function and let the
two inner entry points be `alabel`s inside it (funcdb's `entry-inside` blocker
never fired because splat wrote them as `glabel`s, so the pilot picked this as
`blocker = none`). That touches `asm/` and `config/symbol_addrs_*`, which is a
call for Claude, not for a pilot row.
