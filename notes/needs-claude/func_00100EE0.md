## What it is

Decodes a 1–4 byte big-endian varint at `p` into `*out`, returns `p + n`.
Length prefix = trailing set bits of byte 0: `b&1==0` → 1 byte
(`val = b>>1`); `b&4==0` → 2 bytes (`val = (b>>3)<<8 | p[1]`);
`b&8==0` → 3 bytes (`(b>>4)<<16 | p[1]<<8 | p[2]`); else 4 bytes
(`(b>>4)<<24 | p[1]<<16 | p[2]<<8 | p[3]`). `func_00100F80` is the signed
twin (lb/sra instead of lbu/srl) — solve together.

## Shape already reproduced

Attempt 4 (`build/drafts/func_00100EE0.c`) matches the original byte-for-byte
from `+0x0C` onward **except one duplicated instruction**: CodeWarrior puts
the `srl $v1,$v1,1` of the first branch in the `beql` delay slot only, while
my C (two `(u32)p[0] >> 1` expressions — one in the early-return body, one
after it) emits a second `srl` right after the branch, shifting everything
by +4:

```
mine +008  beql  ... 0x1B ; mine +00C srl v1,v1,1 ; mine +010 srl v1,v1,1 (dup)
orig +008  beql  ... 0x1A ; orig +00C srl v1,v1,1 ; orig +010 andi v0,v1,0x2
```

The `lbu $v1`/`andi $v0` register split at the top came out right by testing
`(p[0] & 1)` first and letting the shift appear only afterwards.

## Update 2026-10-22 (seventh batch): signed twin func_00100F80 MATCHED

The twin is now `src/SLES_539.74/func_00100F80.c` (attempt 2, byte-exact).
Its shape may be the missing trick for the duplicated `srl` here — the
working F80 pattern: `s32 b = *(s8 *)p;` then the 1-byte path is an **early
return** whose body stores the shifted value (`*out = (u32)(b >> 1);`) and
the following paths use the *unshifted* `b`; CW then put the single `sra` in
the `beql` delay slot with no duplicate. For EE0 (unsigned, plain `beq` +
delay `srl` because the shift feeds both sides): try `u32 b = p[0];` tested
via `(b & 1)`, 1-byte path `*out = b >> 1;` early return, and the shared
`b >>= 1` after the return — one shift used on both sides should keep CW
from duplicating it. Byte locals `b1 = p[1];` / `b2 = p[2];` loaded **above**
their respective bit tests were what made the delay-slot loads land in F80.
