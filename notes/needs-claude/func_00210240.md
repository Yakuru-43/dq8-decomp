# func_00210240 (SLES_539.74, 0x210240, 304 B)

Save-record cache insert. Params: `arg0` = big system object (saves as `$s2`,
has a 48-byte record slot at +0x77C0 and a 16-byte tag at +0x77F0),
`arg1` = record being inserted (saves as `$s1`), `arg2` = source descriptor
(saves as `$s0`). Original keeps ONLY s0/s1/s2 + ra, frame `addiu $sp, $sp,
-0x40`; my build spilled 5 s-regs and 0x60 frame because of the `id`/`stamp`
locals (see below).

## Recovered semantics (high confidence)
1. `if (arg1 == 0) return; if (arg2 == 0) return;` (beqz × 2, s0←a2 in the
   first delay slot).
2. `func_002033A0(func_00202520((s32)(arg2 + 0x40)), (s32)(arg1 + 0x18));`
   — args go in the delay slots as usual.
3. `*(u16 *)(arg1 + 0xE) = (u16)(func_00201BD0(func_002061F0(func_00202520(
   (s32)(arg2 + 0x40)), 0)) + 1);` — nested-call chain, byte-exact in my diff
   (region +0x2C..+0x58 matched).
4. `arg1[1] = arg2[4]` (lb/sb), `arg1[4] = arg2[0]` (lw/sw, reloaded with
   `lw $v1, 4($s1)` for the test — do NOT keep it in a reg):
   `if (arg1[4] != 0x10) arg1[1] = 2;` then `if (arg2[4] != 0) arg1[1] = 1;`
   — the two out-of-line `sb` blocks at +0x100/+0x10C with `b` back are
   exactly this; mine reproduces them (registers right after fixing decls).
5. `*(u16 *)(arg1 + 0xC) = (u16)*(s32 *)(arg2 + 0xC);` — the `lw $v0, 0xC($s0)`
   + `sh $v0, 0xC($s1)`-in-the-jal-delay-slot around the
   `func_0020F5E0((s64 *)(arg2 + 0x40))` call: the original keeps the value in
   `$v0` (caller-saved) and stores it in the **delay slot**; `sd $v0, 0x38($s1)`
   right after takes the call result. My `s32 id` local made CW spill to `$s4`
   — write the store BEFORE the call and let CW's delay-slot fill do it, or
   find the formulation that lands it in the delay slot. CW knows
   func_0020F5E0 is pure (it is `return *arg0`), so hoisting the `lw` is legal.
6. `arg1[0x14] = (u32)*(u16 *)(arg2 + 0x14)` (lhu/sw), `*(s64 *)(arg1 + 0x40)
   = *(s64 *)(arg2 + 0x18)` (ld/sd).
7. `if (arg1[1] != 0) return;` (lb/bnez).
8. Compare: `lq $a0, 0x77F0($s2); ld $v1, 0x40($s1); slt $at, $v1, $a0; bnez
   $at, epilogue` — signed 64-bit `arg1[0x40] < tag.lo`, where the tag is
   loaded as a **16-byte `lq` into `$a0`** (call-arg register — the compiler
   seems to hoist the quad load for step 9 and only uses the low half here).
   My `(s64)*(u128 *)` produced `ld $a0, key` first and `lq $v1, tag` — the
   wrong operand roles: try a 16-byte union/struct local (declared `u128`-typed,
   compared via a member) so the load itself is the `lq` into `$a0`.
9. `func_00130FD0((s32)(arg0 + 0x77C0), func_00210370((s32)(arg2 + 0x40)),
   0x30)` — memcpy of the 48-byte record from `arg2 + 0x50`
   (func_00210370 = `+ 0x10` helper).
10. Tail: `ld $v1, 0x40($s1); sq $v1, 0x77F0($s2)` — one **16-byte `sq`**
    whose pair is `(v1, a0)`: low 8 bytes = `arg1[0x40]` (reloaded after the
    memcpy call with `ld`), upper 8 = whatever `$a0` holds, and the only
    meaningful live value in `$a0` is the record pointer `arg0 + 0x77C0` set
    before the memcpy call. So the tag is `{s64 key; void *link;}` with
    link = the record slot itself, and CW folded the two-member store into
    one `sq` reusing the live `$v1`/`$a0`. My version
    `*(s64*)(arg0+0x77F0) = *(s64*)(arg1+0x40); *(s64*)(arg0+0x77F8) =
    (s64)(arg0 + 0x77C0);` compiled to `dsll32`/`dsrl32` (pointer→s64 zero
    extension) + two separate `sd` — do not cast the pointer to s64. Try a
    C++ file with `struct Tag { s64 key; void *link; };` (aligned(16) if
    needed) assigned member-wise from a local then struct-copied, or the
    pair built so `link` is already `void *` in `$a0` when stored.
