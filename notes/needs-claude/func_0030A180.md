## The solved trick (do not lose it)

The 4th arg of both 162xxx calls is **not** constant `0`: the original
sets `$a3` once, before the `beqz $s1`, with `sll $a3, $v0, 12` — the
result of `func_0024C670` zeroed by the `bltzl` delay slot, i.e.
`offset = result << 12;` as a **local assigned after the guard and used
by both calls**. Writing literal `0` gets `daddu $a3, $zero, $zero`
before each call and is 12 bytes short; two per-call `result << 12`
expressions give two late slls. One shared local nails +0x28 exactly.

The original's `if (result == 0) { entry->state = 0; return 0; }` shares
its `return 0` stub with the final `return 0;` at the end of the
param == 0 path (that stub is `.L0030A250`, right after the reset block,
fallen into from the reset), hoists the `state = 0` store into the
`beql` delay slot (runs on both paths, overwritten by `sh $v0` on the
`!= 0` path), and puts `state = 1; return 1;` as `addiu v0; b epilogue`

`b`+`v0=0` stub for that branch and falls into a separate `sh v0` path:
CodeWarrior will not share the two `return 0;` statements as written.

## What was tried

   call; 244 bytes; CLASS structural 54.
2. `result << 12` written at each call site → two `sll` but placed late
