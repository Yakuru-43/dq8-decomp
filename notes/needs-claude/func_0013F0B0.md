## The problem

`build/queue.tsv` row was `todo` (size 32, GS packet write-pointer family,
sibling of func_0013EC20/ECD0/ED40/EDA0/EE00/EFF0/F010 — all matched). The
asm is 5 words:

```
lw   $v0, 0xF4($a0)      ; wp = arg0->0xF4
sll  $v1, $a1, 4         ; arg1 * 16 -> NEW register $v1
addu $v1, $v0, $v1
jr   $ra
sw   $v1, 0xF4($a0)      ; wp += arg1 * 16
```

mwcc always schedules the shift in-place into `$a1` and puts the load in
`$v1` (mine: `lw $v1; sll $a1,$a1,4; addu $v1,$v1,$a1` — byte-identical
operand semantics, wrong registers, score 3). Four shapes tried, all
produced the same allocation:

1. `temp_v0 = M2C_FIELD(arg0, char**, 0xF4); ... = temp_v0 + (arg1 << 4);`
2. one expression, no temp.
3. two locals (`temp_v0`, `temp_v1`), load first.
4. two locals, shift first (declaration-order idiom swapped).

Per the saved-register idiom the allocation should follow declaration
order; here it follows nothing but mwcc's own preference: `$a1` is dead
after the shift so it reuses it, and the load lands in `$v1` instead of
`$v0`.
