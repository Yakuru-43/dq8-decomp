# needs-claude: func_00210EC0

CLASS structural score=46 (45 words differ, 188 vs 192 bytes) — best attempt, `-- -O3`

**Size:** 192 bytes (0x210EC0 – 0x210F80), binary SLES_539.74.

**What it does:** reads the tick counter `D_003E0964` (gp-relative), computes
`cur = tick / 300`, `prev = cur - 1` clamped to 7 when negative, the fraction
`frac = (f32)(tick % 300) / 300.0f`, then writes to `a0`:

- `+0x0`: `(D_003A5910[cur*2] - D_003A5910[prev*2]) * (1 + frac)` (via `madd.s`)
- `+0x4`: `4400.0f` (from `(f32)4400`, i.e. `cvt.s.w` of an integer constant)
- `+0x8`: `(D_003A5914[cur*2] - D_003A5914[prev*2]) * (1 + frac)`
- `+0xC`: `1.0f` stored as an **integer** (`lui 0x3F80` + `sw`, not `swc1`)

Also has a dead `mtc1 $zero,$f3` + `adda.s $f3,f5` / `adda.s $f3,f1` pair.

## Why it cannot match with this compiler

The original's **first** `div` (the `/ 300` for `cur`) is wrapped in a
divide-by-zero trap guard:

```
addiu  $v0, $zero, 0x12C
bnez   $v0, .L00210ED4
div    $zero, $a1, $v0
break  0, 7
.L00210ED4:
mflo   $v0
```

The **second** `div` (the `% 300`, same constant divisor) has no guard.
mwccps2 3.0.1b151 never emits this guard: scratch compile of `a / b` with
variable divisor at -O3 shows plain `div`/`mflo`/`mfhi`, no `bnez`/`break`;
`-help search=div|trap|zero` lists no matching option; `-f div_zero_to_trap`
is "Unknown option 'f'". This is the same wall as func_00210C90
(`notes/needs-claude/`, itoa) — no matched precedent repo-wide; suspect the
original was built with an mwccps2 build/flag that traps division by zero.
The 2026-10-22 compiler sweep (8 builds x flags, see notes/weekly) flipped
nothing, so this needs a compiler-side answer, not a C trick.

Even with the guard, scheduling is off: mine interleaves the two `sll ...,3`
index scales and the second `lui`/`addiu 0x3A5914` pair differently, and
assigns tick/prev to different regs ($a1/$a2 vs orig $a1/$a2/$t0/$t1).

    s32 cur = tick / 300;

    f32 d1;

    d1 = D_003A5914[cur * 2] - D_003A5914[prev * 2];
    out->unk0 = d0 + frac * d0;
    out->unk4 = (f32)4400;
    out->unk8 = d1 + frac * d1;

}
```

## What was tried

1. `out` as `f32 *` with `*(s32 *)&out[3]` — rejected for readability; used
   the struct with an `s32` 4th field, which reproduces the `sw` store.
2. `(f32)4400` vs `4400.0f` for +0x4: `4400.0f` would need `lwc1` from
   .rodata; the original uses `addiu 0x1130` + `mtc1` + `cvt.s.w`, which
   `(f32)4400` reproduces (kept).
3. `-f div_zero_to_trap` (see above — option does not exist in this build).

## Opus attempt 2026-10-24

Guard solved: `// flags: -flag divbyzerocheck` (CodeWarrior `#pragma divbyzerocheck`;
func_00210F80 matched with it). The second `% 300` is unguarded because CW already
checked that divisor. The float math is a lerp, not `d + frac * d`:
`D[prev].x + (D[cur].x - D[prev].x) * t` (`adda.s 0, prev` + `madd.s`), with
`D_003A5910` an array of `{ f32 x, z; }` (D_003A5914 is just `+4`).

Size matches (192 B); what is left:
- The original loads all four floats before the first store. With
  `out->x = lerp; out->y = (f32)4400; out->z = lerp;` CW stores x, then loads z.
  Building a local `Vec4 v` field by field and `*out = v;` (or returning `Vec4`
  by value, C or C++) gives **exactly** the original float sequence, but keeps
  `v` on the stack (extra `addiu $sp` and 4 stack stores, 212 B). Scalar locals,
  a local `Point2`, or a C++ constructor `return Vec4(x, 4400, z, 1)` all evaluate
  z before x.
- Integer registers: original tick `$a1`, 300/cur `$v0`, prev `$a2`, mod `$a3`;
  every version of mine gives tick `$a2`, 300 `$v1`, cur `$a1`. An inline
  `GetPhase() { return D_003E0964 / 300; }` didn't change it.

Next idea: a C++ return-by-value where CW elides the temporary (a ctor with
body assignments, or a member `Set()` on the result), plus whatever puts `cur`
in `$v0`.

// range: 0x210EC0 0x210F80
// flags: -flag divbyzerocheck
#include "common.h"

typedef struct { f32 x; f32 z; } Point2;
typedef struct { f32 x; f32 y; f32 z; f32 w; } Vec4;

extern s32 D_003E0964;
extern Point2 D_003A5910[8];

void func_00210EC0(Vec4 *out) {
    s32 tick = D_003E0964;
    s32 cur = tick / 300;
    s32 prev = cur - 1;
    f32 t;

    if (prev < 0) {
        prev = 7;
    }
    t = (f32)(tick % 300) / 300.0f;
    out->x = D_003A5910[prev].x + (D_003A5910[cur].x - D_003A5910[prev].x) * t;
    out->y = (f32)4400;

    out->w = 1.0f;
}
```
