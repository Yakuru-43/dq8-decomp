16-bit value:

2. loop head: `lw v0,0x8(s0); bnel v0,zero,<read>` — while `field_08 == 0`:
   `field_64 = 0`; `if (field_1C == 0) return -1;`

   (both extern'd; 00105E30 is matched already, 00105D80 is `asm` here);
   `== -1` → return -1; then **the same** v_0x34(-1) test + reset as step 1
   (shared blocks — see walls), fall back into the loop head.
3. read: `result = reader->v_0x24()` (virtual slot 0x24, one arg — `jalr`
   with only `daddu a0,s0` in the delay slot); `== -1` → return -1;
   `result = *(u16 *)field_08; field_08 += 4; return result`.
   The `lw $t9,0(s0)` (vptr) sits in the `bnel` delay slot at the loop exit,
   and the `lw $v0,0x8(s0)` for the read sits in the `bnel` delay slot after

## Where it's stuck

The original shares one copy of [v_0x34(-1) test → reset stores → loop head]
between the step-1 and step-2 sites, materialized as a `failed` flag in
**$s1**: entry `bnez at,.L00105AFC` with `daddu $s1,$zero,$zero` delay slot,
the vtable block tests `bne $v0,-1 → head`, failure edge `b head;
daddiu $s1,$zero,0x1`, and the head block opens `bnel $s1,$zero,<ret -1>`
then the six reset stores and falls into the loop-head test.

return -1;` sites + a `while (field_08 == 0)` loop) makes CW **duplicate**
both blocks instead of tail-merging (380 vs 292 B), rotates the while test

block **before** the flush section, and allocates `failed` to `$s0` with
reader in `$s1` (the original is reader=`$s0`, failed=`$s1`).
