## Wall

The byte sequence has a genuinely unreachable `jal func_00101510; 5×nop;
b -6` block between an unconditional branch and the epilogue. Plain C never
emits unreachable blocks; this likely needs the CodeWarrior C++ EH shape
(roadmap step 7) or a precise try/catch that CW collapses to exactly this
layout.

Best draft: `build/drafts/func_001007A0_cpp.cpp` (diff at +0x0, frame size
0x60 vs 0x40, EH setup extra). Not in `src/`.

## Opus attempt 2026-10-26

**Byte match, blocked only on a missing symbol alias.** The dead block is not
a catch: it is CodeWarrior's handler for an empty exception specification,
`throw()`, which calls `__unexpected(&CatchInfo@fp+0x20)` and spins.
`func_00101510` *is* `__unexpected`. Needs `-O4,p` (at -O3 `addu $fp,$sp`
misses the jal delay slot and the epilogue puts `addiu $sp` before `jr`).

```cpp
// range: 0x1007A0 0x100800
// flags: -O4,p
#include "common.h"

extern "C" {

extern void func_00130458(void);

void func_001007A0(void) throw() {
    func_00130458();
}

}
```
