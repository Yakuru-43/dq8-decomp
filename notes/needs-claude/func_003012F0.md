# func_003012F0 — needs-claude

- asm: `asm/SLES_539.74/game_3012F0.s`, size 0x5C (84 + pad nop), queue row 31.
- What it seems to do: copy the 8-entry (two-word) table at
  `*(u32*)(arg0+0x04) + (*(u32*)(arg0+0x1C) << 6)` into a 64-byte stack
  buffer, then `return buf[1].f1 / 100;` (`mflo` → integer quotient).
- **This is the third instance of the div-guard family**: same wall as
  `notes/needs-claude/func_003010E0.md` and `func_00301200.md`. The new
  data point here: the divisor is a **literal 100**, folded to
  `addiu $v0, $zero, 0x64`, and the original *still keeps* the
  `bnez/div/break 0,7` guard — every C shape I tried makes CodeWarrior
  elide it. So the elision is not value-based range analysis on a
  variable; a provably-nonzero constant divisor loses the guard in my
  builds but not in the original object.

session-10 copy-loop shape from the weekly). Only the guard is absent.

## What I tried (all elide the guard)

1. `return local[3] / 100;` literal — guard elided.
2. `s32 divisor = 100;` variable, then `/ divisor` — elided.
3. `static inline s32 Scale(s32 value, s32 divisor)` helper, called as
   `Scale(local[3], 100)` (divisor enters as parameter, folds after
   inline) — elided.
4. Same helper with `s16 divisor` parameter — elided.
5. `static s32 sScaleDivisor = 100;` global through the helper — CW does
   **not** constant-fold it (emits `lw %gp_rel` instead of the addiu):
   different shape, plus would add .data. Not viable.
6. Dead-branch phi `if (local[3] < 0) divisor = 100; else divisor = 100;`
   — worse (regressed earlier: CW turned `lw $v1, 0xC($sp)` into
   `addiu $v1, $sp, 0xC`, 88-byte diff).
7. `-O2` diagnostic (not committed): guard still absent, regalloc wrecked
   (104-byte diff). Not a flags question — the whole `game` object
   matches at `-O3` for the neighbouring functions.
