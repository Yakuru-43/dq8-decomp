Weird original facts the C must keep:
1. Null check **inverted**: on the int path, `D_003E0B24 != 0` returns 0; the
   int store runs only when the global is NULL (reads absolute 0x114+idx*4).
   Global is read twice on that path: test load + reload in the `beql` delay
   slot of the null check (so the test load also serves the float path,
   which never null-checks).
2. Both stores sit behind a **redundant** `if (slots[1].type == 3)` (a2==3 was
   already guaranteed); the entry **load** executes unconditionally (guard's
   delay slot), only the **store** is guarded. `load; if (guard) store` is the
   shape that reproduces this; `if (guard) { load; store; }` gives
   `bne; nop; load` and 16 bytes extra.
3. `ret1` stub sits **after** the float arm; three paths share it (one
   `return 1` at the end, per the one-return-stub idiom).
