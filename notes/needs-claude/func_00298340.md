## What the asm does

Searches a 32-entry table (stride 0x20) at `a0` for an entry whose
`+0x64` word equals `a1`, returning `entry + 0x48` (else 0). But the
shipped bytes contain a scheduling artifact: the `beql` at 0x298358 has
target == fall-through (imm=1, verified from extract/SLES_539.74.bin word
0x50A30001), so `daddu $v0, $a2, $zero` in its delay slot executes
**unconditionally** — the reference function returns `base + 0x470` for
every input (never 0), and the compare is dead code. (Its twin
func_00298380 likewise always returns 31.) Same family as the
`func_00182130` idiom case: CW b151 -O3 duplicating a one-instruction
if-body into the delay slot of the inverted branch.
