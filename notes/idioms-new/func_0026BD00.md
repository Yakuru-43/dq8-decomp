# Idioms-new

## Out-lined call block (b-back + duplicated store): type the call argument pointer
Sign: `if (o->f != 0) { call(o->f); } <long store tail>` gives `beqz, nop, jal,
nop, fall-through tail` in the original, but every plain-C spelling (typed
struct, goto, dead store in the then-arm, store moved before the if) compiles
to the rotated layout: `bnez` to an out-of-line 2-word call block placed after
the tail, a `b` back into the middle of the tail, and the tail's first store
(and any early `addiu v0,1`) duplicated. CLASS structural, ~12 words too long;
Qwen notes call it the "if-block rotation wall" (func_0026BA60).
Fix: type the field and the callee parameter as **pointers** (`void *field_28;`
and `void func_002784F0(void *);`), even when the asm shows only `lw/beqz/jal`.
The integer typing makes CodeWarrior outline the call block; the pointer typing
keeps it in place with the beqz+nop fall-through. Test this FIRST on any
free/mem/destructor-looking `if (o->f) free_like(o->f);`.
Example: src/SLES_539.74/func_0026BD00.c
Solved: func_0026BD00 (2026-10-30, Qwen, factory-2)
