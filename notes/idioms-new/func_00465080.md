## Two equal multiples must be spelled differently, or CSE hoists one into the other
Sign: a function passes `x * K + c` as the 5th (`$t0`) arg of a call inside an
`if`/`else`, then `x * K - d` as the 5th arg of several calls after it. The
original recomputes the multiply **per region** (each region gets its own
`sll`/`addu`/`sll` chain, results in `$v0`/`$v1` temporaries), while a single
`x * K` in C gets CSE'd: CW computes it once inside both branch paths, sinks
it into a callee-saved `$s1` and rematerialises `±d` per call — 12-16 bytes
short, CLASS structural.
Fix: spell the branch expression so it builds the same instructions but a
different tree: `((x * 33) << 1) + 4` in the branch vs `x * 66` after the
merge (`33 * 2` folds to 66 at parse, a plain shift of the constant does not).
Then the tail value used **twice** (`w - 2`) must be a named local live across
the calls, or CW rematerialises it into `$t0` per call instead of allocating
`addiu $s2,$s1,-2`; values used once (`w - 20`, `w - 25`) stay inline.
