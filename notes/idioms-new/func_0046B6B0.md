## Init/ctor loops with no entry guard: write do-while, the `for` form gains a `b`
Sign: a constructor/init function whose loops enter the body **unconditionally**
(`jal f; daddu a0,$sX; addiu $sX,$sX,N; addiu $sY,$s0,END; sltu $v0,$sX,$sY; bnez $v0,<top>; nop`,
first body instruction right after the previous store, no `b`/`beqz` before it).
A `for (p = start; p < end; p += 8) f(p);` gives CW 3.0.1b151 -O3 an extra
unconditional `b` before each loop (entry guard duplication): mine 12 B longer,
CLASS structural. (idioms.md "Loop with a top guard" is the opposite case — there the
*original* has the pre-test.)
Fix: `p = start; do { f(p); p += 8; } while (p < end);` per loop — the bottom `bnez`
and the loop-body order then come out exact, including the bound `addiu` recomputed
per iteration next to the `sltu`.
Also, same function: a `sw $zero,off($s0)` that belongs **in the delay slot** of a
later `jal` must be written **before** the call's C statement (CW sinks the last
pending store into the slot; written after the call, the *previous* store wins the
slot and everything shifts). And a trailing `return self;` gets its
`daddu $v0,$s0,$zero` parked mid-store-block, no placement needed.
Example: src/CASINO/func_0046B6B0.c

factory-6 (memset(self,0,0x2C) + same 10-store cluster: source order must copy
this example's `0,C,10,8,14,18,1C,20,24,28` - an ascending source store order
gets reordered (score 3); the three `= 0` stores (1C,24,28) must be written out)
