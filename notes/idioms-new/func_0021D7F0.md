# Idioms-new

## Both if/else arms land on one `b; nop` stub: a single explicit `return;` after the if/else, inside the outer guard; clamps keep their store in the branch delay slot
Sign: each arm of an if/else ends with a guard + conditional store (`bc1f`/`bne`
skipping one store), and in the original both arms land on a shared 2-word block
`b <epilogue>; nop` placed between the arms — one arm falls into it, the other
reaches it with a `b` back (a b-to-b, no threading), while the guard branches skip
straight to the epilogue. First drafts written without the shared exit come out
4+ words short and CodeWarrior DCEs one store of an `x += K; if (x > K) x = K;`
clamp (the unconditional store looks dead): CLASS structural, size short.
Fix: type the object from the module's initialiser function (neighbour like
`func_0021DB20`), then write
`if (o->active != 0) { if (t != 0) { if (t == 1) { o->val += 1.0f; if (1.0f < o->val) { o->val = 1.0f; } } } else { o->val -= 1.0f; if (o->val < 0.0f) { o->val = 0.0f; } } return; }`
— one explicit `return;` at the end of the outer if, after the if/else: both arms
flow into CW's single stub, the guards thread to the epilogue, the later arm keeps
its `b` back to the stub. Keep the step in place (`o->val += 1.0f`, not
`f32 next = o->val + 1.0f`) — the in-place form gives `add.s $f0,$f0,$f1`/
`sub.s $f1,$f2,$f1` operand order; a temp reverses the add. Reading `o->val` again
in the guard does NOT add an `lwc1` (register reuse), so don't cache the sum.
