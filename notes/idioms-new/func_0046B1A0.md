## `sq $zero, N($sp)` prologue for a float[4]: assign `0` to a `u128` union member, not `= {0,0,0,0}`
Sign: function starts `addiu $sp,$sp,-0x20; sd $ra,0($sp); sq $zero,N($sp)` (N a
16-aligned stack slot), and each float of that slot is later stored individually
(`swc1`, or `lui/sw` for a constant like `1.0f`) before a call gets `addiu $aN,$sp,N`
in its delay slot (m2c shows `s128 sp10 = 0; /* compiler-managed */`).
Drafting the local as `f32 v[4] = {0, 0, 0, 0};` compiles the init to a byte-by-byte
memset loop (`addiu $v0,$zero,0x10; addiu $v1,$sp,0x10; beqz; sb $zero,0($v1);` ... ~24
words, CLASS structural) and inflates the frame.
Fix: declare it as a union and zero the quad member:
```c
typedef union Vec4B1A0 {
    /* 0x00 */ u128 q;
    /* 0x00 */ f32 v[4];
} Vec4B1A0;
Vec4B1A0 vec;
...
vec.q = 0;            /* sq $zero, 0x10($sp) */
vec.v[0] = x0; ... func(D_003E1B9C, vec.v, i3);
```
`u128` is `unsigned __int128` from common.h; CW aligns the local to 16 and emits the
single `sq`. The trailing constant store (`v[3] = 1.0f` → `lui $v0,0x3F80; sw`) and the
per-element stores come out in the original's scheduled order from plain sequential C.
Matched on the 2nd try (1st try was the memset loop).
