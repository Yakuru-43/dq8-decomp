## Tagged-arg select as one ternary: `tag == 1 ? (s32)*(f32 *)&bits : bits` puts the bits load in the `bnel` delay slot
Sign: `lw $v1,0($a0); addiu $v0,1; bnel $v1,$v0,<join>; lw $a0,4($a0); lwc1 $f0,4($a0);
cvt.w.s $f0,$f0; mfc1 $a0,$f0` then the join straight after the `mfc1` (no `b`). The tag==1
arm reads the float **directly at self+4** (`&bits`), it does **not** dereference `bits` first.
Wrong spellings: mutating the parameter (`arg0 = (s32)*(f32 *)(*(s32 *)(arg0 + 4) + 4);`) or
a separate `kind = arg0;` local — CW then puts the conversion out-of-line with `bne` and
**duplicates the join** (+16 B, CLASS structural ~79). A previous needs-claude note for this
family had chased exactly that double-deref shape and called the residual `lw $a3,4($sp)`
unsolvable; the correct arm assignment makes it disappear.
Fix: one ternary into one local, `kind = (arg0->tag == 1) ? (s32)*(f32 *)&arg0->bits :
arg0->bits;` with `TagArg { s32 tag; s32 bits; }` (the type the sibling opcode handlers use),
`arg0` typed `TagArg *` and dead after the two loads so `kind` lands in `$a0`.
