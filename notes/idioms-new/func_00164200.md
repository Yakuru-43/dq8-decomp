## Two-arm select with a shared float tail: write the ternary so the tail lands after the cold arm
Sign: `if (c) q = <div block 1>; else q = <div block 2>;` then one shared `return (f32)q / K;`.
As if/else CW lays the tail right after the **inline** arm (`mflo` falls into it), puts the
cold arm past the tail and adds a `b` back plus one more `b`/`nop` pair (mine 8 B too long,
CLASS structural, score 23); the original has the tail **last**: the inline arm joins with
`b <tail>; mflo $v0` and the cold arm falls through. Related sign in the same pair of
functions: writing the outer range test as `v < -49` puts `v` in `$v1` and the second test's
result in `$v0` instead of `$at` (score jumps 23 → 29); the **`<= -50`** spelling (same
value) restores `addiu $v0,$v0,-0x80` and both `slti $at` — for negative-constant compares,
try the `<= C-1` form before blaming the allocator.
Fix: one ternary with the **inline arm's expression first**:
`q = (v > 0) ? ((v - 49) << 7) / 78 : ((v + 50) << 7) / 78;`
CW then keeps the inline arm but branches over the tail from it (`b` + `mflo` delay slot)
and places the cold arm immediately before the tail. Pairs with func_001C57D0's
"write the ternary, not if/else" (there for single-op arms folding into the delay slot);
here the arms are real blocks and what moves is the tail.
