## Tested global's branch polarity follows its C type: declare pointer globals as `T *`
Sign: a top-of-function `if (D_g != 0) { hot } else { cold }` compiles inverted — CW emits
`bnez $v0, <hot>` with the **cold (null) path inline** and the hot block after a return
stub (CLASS structural, size already equal after fixing the section attribute). The
global is loaded `lui/lw` (it is absolute, declare `extern ... __attribute__((section
(".data")))`, a tentative `s32 D_g;` goes gp-relative and shifts the whole function).
Fix: declare the global as a **pointer**: `extern char *D_g __attribute__((section
(".data")));` and test it plain (`if (D_g != 0)`; `if (D_g)` also works). With a pointer
type CW keeps the natural layout `beqz $v0, <cold>` + hot path inline; with `s32` it
inverts the if/else. (SKILL.md's integer-test idiom is about *call results* and
branch-likely; this is the source-side type choice for globals feeding a plain beqz.)
