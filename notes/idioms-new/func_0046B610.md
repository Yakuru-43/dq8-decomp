## Virtual-count limit: the param'd virtual past ~64 fails to parse
Sign: a hand-built class for a deep `$t9` slot (`u8 pad0[N]; virtual ...` +
stub virtuals, idioms.md "Indirect call through $t9") where the *one* virtual
that takes parameters is beyond roughly the 64th virtual: mwccps2 reports
`declaration syntax error` pointing into that declaration's parameter list and
`function call ... does not match 'Cls::m(int)' (non-static)` at the call —
the parser swallows the prototype as K&R `(int)`. Moving the struct outside
`extern "C"` changes nothing; no-arg stubs above it parse fine, so the body
looks healthy and the cause is invisible.
Fix: count the virtuals in hex against the target slot: slot 0xB4 = 0x08+4*43
means exactly **43** stubs (`f00..f2a`), not `f00..f42` (= 67, which fails);
slot S needs (S-8)/4 stubs. Verified points: 44 total virtuals with a `f32 *`
param compile; 68 fail. Exact threshold not bisected — keep the list at or
below the needed count and check (S-8)/4 by hand. (If a slot past ~0x100 is
ever needed, this technique may be a dead end; a plain function-pointer table
gives `$v0`, not `$t9`.)
