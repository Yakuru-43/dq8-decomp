## Duplicated guard `bltz` around a call + kept prologue `x = 0`: early-return guard plus a re-checked `if` around the call
Sign: right after the prologue saves, a `daddu $sN,$zero,$zero` (a local
pre-initialized to 0 that the compiler did NOT fold away), then
`bltz $argX, <ret-0 stub>` with a useful instruction (often a `sq` spill) in
its delay slot, then a second `bltz $argX, <skip>; nop` that jumps over one
call. Same register, same sign test, two branches.
Fix: write the guard clause and wrap the call in a re-checked `if` on the same
condition, and give the local a `= 0` initializer at declaration:
```c
    s32 count = 0;

    if (port < 0) {
        return 0;
    }
    if (port >= 0) {
        count = func_0038D360(port, &info);
    }
```
The `if` without an `else` makes CodeWarrior emit the block skip in plain
`bltz`/`nop` form (not `bgezl`); with an `else` it inverts to `bgezl` and
moves the copy into the delay slot. The `= 0` initializer survives
const-folding only because the `if (port >= 0)` path can skip the
assignment — without the re-checked `if`, CW deletes the `daddu sN,zero,zero`.
Guard clause alone (no re-check) gives `bgez` + unconditional `b` to the stub
instead.
