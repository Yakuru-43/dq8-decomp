## Scan-down clamp loops: `for(;;)` with a `continue` keeps the `bgez` back-edge; hoist the start copy above the `<= 0` guard
Sign: three blocks `blez <val>, <cold sw zero>` / `<cur>=<start> in the delay slot` /
`subu v1,val,cur; blezl v1 →dec; cur--; b end; sw v1,(out)` / `dec: bgez cur →top; nop;
sw val,(out)` — a loop that enters its body **unconditionally** (first iteration skips the
`cur >= 0` test) and stores either `val - cur` or `val`. The callee also reads `$t0/$t1/$t2`
at entry with no prologue: those are parameters 5..7 (callers load them with
`daddu $t0,$sN` / `addiu $t2,$zero,K` before `jal`) — declare plain extra params (cf.
func_004626B0.md, which saw the 5th-in-$t0 for window calls only).
Fix: per block:
```c
cur = used;                 /* above the guard: CW puts the copy in the blez delay slot */
if (total <= 0) {
    *out = 0;               /* cold, with `b` to the next block; in the LAST block CW
                               sinks it into the blezl delay slot to the epilogue */
} else {
    for (;;) {
        diff = total - cur;
        if (diff > 0) { *out = diff; break; }
        cur--;
        if (cur >= 0) { continue; }
        *out = total;
        break;
    }
}
```
`if (cur >= 0) continue;` (not `if (cur < 0) break;` on the other side) is what emits the
plain `bgez cur →top; nop`. A `static` helper for the loop is NOT inlined at -O3 (three
`jal`s + frame, CLASS structural); write the three copies out. A `do { } while (cur >= 0);`
re-tests after the loop — two store sites are needed, so keep `for(;;)` + breaks.
