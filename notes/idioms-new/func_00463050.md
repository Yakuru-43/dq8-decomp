## Overlay externs: `section(".data")` for absolute addressing; short names for cross-overlay calls
Sign: an `extern` to a global outside `.sdata`/`.data` (here `D_44F0F0`, SHOP
overlay data) compiles to `lui $a0,0x45` + `addiu $a0,$gp,0x0` in try_match
(gp-relative, 4 bytes short, CLASS structural); and a same-overlay call
written in the 8-digit twin style (`func_00379600`) links red in
`make` (`undefined reference`) although verify.py says MATCH.
Fix: declare every such global as
`extern M2C_UNK D_44F0F0 __attribute__((section(".data")));` — that gives the
original's absolute `%hi`/`%lo` pair (same fix as the `.sdata` rule in
notes/idioms-new/func_0045F750.md, but `.data`, not `.sdata`). For callees
outside your overlay, use the **short** asm name (`void func_379600(s8);`,
`s32 func_2D5410(s32, s32);`) — those are what
`linker/<BIN>_undefined_funcs_auto.txt` defines; the 8-digit form is only for
functions of the *same* overlay (its objects define the C names). Check both
with the real build, not just try_match: only `make` catches the link names.
