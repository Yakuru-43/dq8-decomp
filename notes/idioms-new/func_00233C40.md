## Base+index `addu` with the load and the multiply in each other's registers: split the expression
Sign: a loop body computes `var = *(T **)(arg0 + 0x1C) + i * 0x830;`. Register-only
diff (CLASS reorder+register, 7-8 words): mine `lw $v1,0x1C($a0)` then the constant
multiply chain in `$a3` and `addu $a3,$v1,$a3`; the original `lw $a3,0x1C($a0)` first,
the multiply chain in `$v1`, `addu $a3,$a3,$v1`. The result variable lives in `$a3`
across the loop, and swapping the operands of `+` in the C changes nothing (tried both
orders — unlike "Register clusters swapped around an `or`/`addu" in idioms.md, where
that fix worked).
Fix: split the assignment in two statements so the load writes the result variable
directly and the multiply lands in a scratch:
```c
var_a3 = *(char **)(arg0 + 0x1C);
var_a3 += var_t1 * 0x830;
```
CW then emits the `lw` into `$a3` and schedules the multiply into `$v1`, exactly the
original. Also from this function: `if (arg1 == *(s32 *)var_a3)` for a `beq $a1,$v1`
where `*(…) == arg1` gives `beq $v1,$a1`.
