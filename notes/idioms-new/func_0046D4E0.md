## `addiu $t0` in a `jal`'s delay slot that a later `lw $t0` "kills": it is the call's 5th parameter
Sign: a call's delay slot computes `addiu $t0, $vX, -K` whose result looks dead — the
next block starts `lw $t0, off($sp)` — and the same sum reappears (recomputed, unused)
before a later sibling call too. Drafting it without the argument leaves you ~32 B short
(CLASS structural) because both copies are missing from your compile.
Fix: `$t0` is parameter 5 of the callee (cf. func_004626B0.md: params 5..7 arrive in
$t0/$t1/$t2). The delay-slot store runs **before** the call, so the value is consumed by
that very `jal`; the later `lw $t0` prepares the *next* call's arguments and only looks
like it overwrites a dead value. Declare the callee with the extra parameter and pass the
shared expression at each call site — CW recomputes it per call across intervening `jal`s
(no CSE, no stack temp). Check which register feeds the delay-slot `addiu`: if it was set
by an `addu` of two stack loads nothing else uses, those loads are the 5th arg's operands.
Example: src/MENU/func_0046D4E0.c (both `func_2D6110` calls take
`(b + d - 0x4A)` in $t0; live 4th args `a - 8` and `a + c - 0x4A`)
