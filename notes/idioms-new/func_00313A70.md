# Idioms-new

## A whole `*dst = *src` coalesces into one word loop: assign the sub-structs separately
Sign: a struct-copy function whose original is block-by-block (unrolled scalars, a
counted copy loop per array region, unrolled scalars again), but `*dst = *src` on
the full struct compiles to ONE `for`-shaped word loop (`addiu $a2,$zero,N/8` +
`addiu $a2,-1` + bottom `bgtz`, walking `t0/a3 += 8`) covering the whole object —
mine 48 B vs 192, CLASS structural. Nesting plain int structs in the type does not
help; the coalescing fires on the whole-struct assignment itself.
Fix: give the array regions wrapper struct types (`struct Pairs8 { Pair8 item[8]; }`,
`struct Table { Pair32 item[57]; }`) and write the function as separate member
assignments: scalars one per line (`dst->field_00 = src->field_00;`), each array
region as ONE sub-struct assignment (`dst->table = src->table;`). CW then emits its
counted-copy loop per sub-object (byte regions: `lb/lb/sb/sb` pair per iteration,
step 2; word regions: `lw/lw/sw/sw`, step 8) and keeps the scalars as plain pairs —
the original matched in 1 try after this change (the hand-written `for` loops give
indexed `sll/addu` + `slti` loops and even `lwc1/swc1` for the struct copy: wrong).
`return dst;` at the end gives the `daddu $v0,$a0,$zero` in the tail block.
