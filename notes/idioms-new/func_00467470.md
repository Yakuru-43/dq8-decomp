## Loop base from a global: its own local assigned before the counter init, not inlined in the entry expression
Sign: a table-init loop `while (j < K) { e = (T *)(D_g + j * 16); ...; }` where the
original's pre-loop order is `lw $a3, %gp_rel(D_g)($gp)` **before** `daddu $t0,$zero,$zero`
(counter init), and in the body the shift is `sll $v1,$t0,4`, `addu $a2,$a3,$v1`, with the
exit test `slti $v1,$t0,K` sunk *between the first and second store*. Writing the entry
as `entry = (T *)D_g + j;` (no base local) gives base and entry sharing `$a2`, the shift
value in `$a3`, and the `slti` hoisted up right after the `addiu` increment: everything
else identical, CLASS reorder+register, score ~10, size already equal.
Fix: give the base its own pointer local, assigned as a statement directly above the
counter init: `base = (T *)D_g; j = 0; do { entry = base + j; j++; ... } while (...)`.
CW then keeps the base live in `$a3` (loaded before the counter init), gives the shift
`$v1`, and the `slti` slides down behind the first store on its own. The constant
multiply `i * 1520` in a sibling loop folded to the `sll/addu/sll/subu/sll` chain
unprompted. Do-while form per notes/idioms-new/func_0046B6B0.md (no entry guard).
