## Two stores through one pointer field: write them as separate full member chains, not a reused pointer local
Sign: each switch arm (or repeated block) stores to two fields of the struct
behind a pointer field (`lw $v0,0x58C($s1); sw $a1,0xE0($v0); lw $v0,0x58C($s1);
jal f; sw $v1,0xE8($v0)`) — the SAME field is loaded twice with no call between
the loads, and the table pointer is `$v0` while the stored constant is `$v1`.
A `slot = arg0->table;` local used for both stores gives both loads in `$v1`
and the constant in `$v0` (register-only diff in every arm, score ~48); one
fully-folded load is 4 B short per arm.
Fix: write the first store through the pointer local (`slot = arg0->table;
slot->unkE0 = K;`) and the second as its own complete access chain
(`arg0->table->unkE8 = V;` — no local). CW must reload the field after the
store (it cannot prove the store doesn't alias the field), and the chain's
fresh temporary takes `$v1`, matching the original's coloring. If an arm's
second value is a plain `sw $zero` and its E0 constant is not also a call
argument (no `addiu $a1` in the original's arm), write BOTH stores as chains
in that arm; keeping the local there swaps `$v0`/`$v1` again.
