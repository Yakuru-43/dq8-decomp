## Branch delay slot holds a `daddu $aN,$sX` with no user: the next call takes that arg
Sign: your build emits a plain `beq`/`beqz` + `nop` where the original has the
`-likely` form with a register-to-register copy into an arg register
(`beql $v1,$v0,<target>` + `daddu $a0,$s0,$zero`) whose value is only read by a
`jal` several instructions **after** the branch target. The copy looks
redundant (the arg is re-set right before that `jal`'s own delay slot), which
is why plain C won't schedule it there: you wrote `f()` with no argument.
Fix: give that callee the parameter (`extern f32 func_004751B0(char *);` and
`func_004751B0(r)`). CodeWarrior then hoists the arg copy above the guard into
the branch delay slot and the branch becomes `-likely`. Unlike
[[func_00161450]] (a global field *loaded* into `$aN` early), here the value is
already in a callee-saved register and only the hoisting is visible.
Example: src/BATTLE/func_00478A70.c (`actor->field_F4 < func_004751B0(r)`)
