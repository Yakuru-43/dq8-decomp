## Switch compare chain emits in reverse case order

Sign: the original dispatches on one integer with a chain
`addiu $v0, K1; beql $v1, $v0, L1; addiu $v0, K2; beql $v1, $v0, L2; b Lend`
(two+ values, each case jumps forward, default falls through to a bare `b`).
An `if/else if` gives an inverted chain (`bnel`, the last case's block moved
after the other blocks' code); a `switch` written in chain order gives the
chain reversed.

Fix: write the `case` labels in **reverse** of the chain's compare order
(`case 13` before `case 9` when the asm compares 9 first). This also puts
the later-compare case's block first in the layout, so the earlier case's
loop body/test fall through into the shared exit block instead of jumping
over the other case (kills a `b` + `nop` pair).

Example: src/BATTLE/func_00468F50.c — chain [9][13], layout
[case-13 peel][case-9 body][case-9 test][shared exit]; `if/else if` scored
structural 36, `switch` in order 45, reversed cases MATCH (0).
