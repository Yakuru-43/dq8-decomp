## Scan loop that tests `*p` in the condition and assigns the `s8` inside the body
Sign: a `while` scan that both tests the byte for 0 and compares it with a
constant; the post-loop guard is a raw `beql $v0,$zero,<epi>` on the loop's `lb`
value, but mine has a `dsll32 $v0,$v0,24; dsra32 $v0,$v0,24` pair right before
the `beql` (2 extra words, CLASS structural, every later line shifted).
Comparing the `s8` after the loop gives the pair, and so does `if (*p == 0)`
when the `s8` was assigned in the condition (value-numbering routes `*p`
through the shifted `c`).
Fix: test `*p` in the condition and assign the `s8` as the body's first
statement, then test `*p` after the loop: `while (*p != 0) { c = *p; if (c ==
':') break; p++; len++; } if (*p == 0) { return -1; }`. The `!= 0` test keeps
the raw `lb` value (MWCC value-numbers the post-loop `*p` to it); the shifted
pair stays only inside the body for the constant compare.

## `addiu $aN,$aN,1` in a `beqz` delay slot where the exit skips it: post-increment the store
Sign: a copy loop with a bounded counter whose exit `beqz`/`bnez` has the
cursor `addiu` in its delay slot (so the increment runs on the break path too,
and a later `sb $zero,0($aN)` terminates one byte further); hand-written
`*dst = c; if (n >= k) break; dst++;` puts the `sb zero` after the branch and
the `addiu` out of the delay slot (reorder+register diff).
Fix: write the store as a post-increment: `*dst++ = c;` before the break test —
the increment is then unconditional in the C, and CW schedules it into the
branch delay slot. (The hand form also differs semantically: it terminates at
`dst`, not `dst + 1`, so a diff this small can hide a real off-by-one.)
