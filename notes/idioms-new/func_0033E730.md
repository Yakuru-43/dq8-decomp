# Delay-slot float store: an `else { x = v; }` that is just one store is a pre-guard store

## else-store scheduled into the `bc1t` delay slot
Sign: original has the compare, then `bc1t <cold>; swc1 <val>, D_x` — the else store sits
in the branch delay slot (executes on both paths; the cold arm re-stores its own constants
with `swc1 $f0`/`sw $v0` and `b`s back to the instruction *after* the delay slot). Writing
`if (sum < 0.0f) { reset } else { D_x = sum; }` gives `bc1t cold; nop` + `swc1` below (one
word too long, CLASS structural).
Fix: write the else's store as an unconditional statement before the guard:
`sum = a + b; D_x = sum; if (sum < 0.0f) { D_x = 0.0f; D_y = -2.0f; }`. CW sinks the
`swc1` into the branch delay slot; the taken path is corrected by the cold block, and both
paths join at a fresh `lwc1` of the global (so keep the next test reading the global, not
the local). Works for int too. Check it by branch targets: a delay-slot store on a taken
branch whose target overwrites the same field is the tell.
