## compare-chain switch: tests in reverse source order, default assigned before the switch
Sign: a switch that stays a compare chain (`addiu $v0, CASE; beql $s0, $v0, ...`)
whose tests run in the reverse of what looks natural, and where the default value's
`li`/`mtc1` is emitted *before* the first test. Floats: two `f32` locals whose
`$f1`/`$f2` roles are swapped in the diff.
Fix: write the `case` labels in the reverse of the asm test order (first test in asm
= last `case` in source). Assign the default value *before* the `switch` instead of
writing a `default:` arm (`f32 rate = ...` style: `rate = 1.0f; switch (type) {...}`)
— CodeWarrior sinks that store ahead of the whole chain, and the default path then
just falls out / jumps past it. Float registers follow declaration order like saved
int registers: if `$f1`/`$f2` are swapped, swap the `f32` declarations.
Example: src/SLES_539.74/func_00327810.c (chain tests 0x50,0x4F,0x4E,0x1A8 = source
order 0x1A8,0x4E,0x4F,0x50; `rate = 1.0f;` before the switch emits
`lui 0x3F80 / mtc1 $f2` before the first `beql`; `f32 rate;` before `f32 v;`)
