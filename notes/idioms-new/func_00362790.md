## Null-check guard CSE'd into the loop base where the original reloads the global: name the mid-call result first
Sign: the original loads a global twice — `lw $v1,%gp_rel(D)($gp)` + `beqz $v1,<epi>`
at the top, then a second `lw $s0,%gp_rel(D)($gp)` after an intervening `jal` (whose
result `daddu $a0,$v0` still carries to a later call) — and mine has one load feeding
both (the guard tests the loop-base register). The CLASS line is structural/reorder
with everything after the missing load shifted; size may still print equal because
try_match compares words, not the load count.
Fix: give the intervening call its own statement and named local **before** the
second global read, so the read is a separate source statement after a call:
```c
if (D_arr == 0) { return; }
handle = func_0015F490();       /* named result, separate statement */
arr = D_arr;                    /* CW reloads here instead of reusing the guard's lw */
func_001419A0(handle, arr->count, 1.0f);
```
Inlining the call as `func_001419A0(func_0015F490(), arr->count, 1.0f)` lets CW CSE
the guard's load into the base. Related (not the same): idioms.md "Field load CSE'd
where the original reloads" (member fields, needs inline member functions).

Same function, loop-back order: `addiu i,1` then `addiu base,0x500` before the bottom
test — a `for` whose body bumps the cursor and whose increment bumps the counter emits
them reversed (reorder-only, 2 words); write **both** bumps in the body, counter first,
with an empty `for` increment: `for (i = 0; i < n;) { ...; i++; arr++; }`.
