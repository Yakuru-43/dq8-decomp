## A `sw` in a guard `beqz`'s delay slot is an unconditional store written above the test

**Sign:** the original has `lw $v0,%gp_rel(D)($gp); beqz $aN, <late block>;
sw $v1,0xC0($v0)` — the store feeds neither branch and sits in the `beqz`
delay slot, so it runs on BOTH paths (the late block does not repeat it).
Writing the store inside the `if` arm gives `beql <late>; <late block's
first load hoisted into the slot>` and one load too many
(CLASS structural, arms otherwise right).

**Fix:** the store was a plain statement before the branch, not part of
either arm — CW sank it into the guard's delay slot:
```c
*(s32 *)(D_003E0B24 + 0xC0) = value;   /* runs on both paths */
if (str != 0) {
    func_001340C0(D_003E0B24 + 0xC4, str);
} else {
    func_001340C0(D_003E0B24 + 0xC4, D_003C8790);
}
```
The pointer's `= 0` init also wants to be the declaration initializer
(`char *str = 0;`) so CW schedules it before the `slti` of the arg-count
test; with `$a1` still live there, the allocator parks `str` in `$a2` and
emits the original's `daddu $a1,$a2,$zero` before the `jal`.
