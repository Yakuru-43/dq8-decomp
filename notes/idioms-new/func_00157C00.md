## The same bitfield stored twice: write two assignments, CW keeps both RMWs
Sign: two `lhu; and ~mask; or K; sh` (or `lbu`/`sb`) RMWs on the SAME word and
bit window — one ORing a folded `daddiu $r,$zero,1<<pos`, the other the
"store 0" lowering (`andi $r,$zero,mask; sll`). A single assignment gives one
RMW (mine 8–12 B short, CLASS structural, everything else identical).
Fix: write the value twice in source order: `o->val = 0; o->val = 1;`. CW
does not merge read-modify-write stores across each other, so both survive.
Common in these init functions (reset then enable). Check the asm for
repeated mask constants with different OR values.
Also, same function: an 8-byte global read as `lui %hi; ld %lo` + `sd` comes
out `ld $aN,0($gp)` (small data) with a plain `extern u64 D_...;` — CW puts
an 8-byte variable in `.sdata`. Declare it the way the sibling TU does:
`extern s64 D_003A0F30[12] __attribute__((section(".data")));` and index it
(`D_003A0F30[1]`); `.data` forces the absolute `lui/ld`. See
src/SLES_539.74/func_00157B80.c for the sibling spelling.
