## Locals declared mid-block: `expression syntax error` on a perfectly good declaration
Sign: `mwccps2` fails with `expression syntax error` pointing at the *name* in an
ordinary `s32 x = f();` (or `fptodp`-free plain int local) that sits after another
statement inside the same block; moving it above the statements compiles fine.
Fix: this build compiles C89 — declare every local at the top of its block and
assign afterwards (the top of a fresh `{` block is fine, e.g. inside the loop body).
Not a reserved-word issue, and no flag changes it.
Example: src/SHOP/func_00460F70.c (all five locals declared at the top; `best =
99999; i = 0;` assigned just before the loop — the assignment order there also
sets which one gets `$s0`).
