# A constant-count scan written rolled is NOT unrolled: hand-write the blocks and recompute the cursor from the base parameter
Sign: N identical load/test blocks back to back (here 4), each entry block starting with a
`slt $at,$v0,$tX; beqz $at,skip; nop; daddu $v0,$tX,$zero` clamp, and the continue branch
`blezl $vN,<next>; addiu $v0,$a1,-2K` with the delay slot recomputing the cursor as
base-param minus a constant (`-2`, `-4`, `-6`), return stubs `b <epi>; daddu $v0,$a1,$zero`
/ `nop`. No loop counter anywhere.
Fix: a `for (k = 0; k < 4; k++)` with the early `return` in the body stays ROLLED at `-O3`
(CW keeps `slti $v0,$a0,4; bnel` and decrements the cursor in place: `addiu $v0,$v0,-2`,
CLASS structural, ~100 B off). Write the blocks out by hand and **recompute from the
parameter** in each block: `i = idx - 2;` ... `i = idx - 4;` ... `i = idx - 6;` (not
`i -= 2`) — CW's constant folder then emits the `addiu $v0,$a1,-2K` delay slots and the
test direction (`blezl` to continue, `b` to the shared epilogue) falls out. A dead first
parameter is the natural home for a `p3 * p4` product computed before the scan.
Listing note: a line `mult $rd, $rs, $rt` (3 operands, single word) is the autodecomp
fused display of `MULT $rs,$rt` + its adjacent `MFLO $rd`; the real object has both
words, so plain C `x = a * b;` reproduces it.
