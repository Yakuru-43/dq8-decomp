## 32-byte stack scratch filled pair-wise: an explicit do-while, not a struct assignment
Sign: a 32-byte local at `0x20($sp)` filled from a global by a loop of 4 iterations
that reads/writes two words at a time (`lw 0(a2); lw 4(a2); sw 0(a1); sw 4(a1);
addiu a2,8; bgtz count; addiu a1,8`), with the trip count preloaded
(`addiu $a0,$zero,0x4`) and decremented inside the body, `bgtz` plain at the bottom.
Later a pointer into the same local is passed as a call arg at a 16-byte stride
(`sll v0,idx,4; addu v0,v0,sp; addiu a2,v0,0x20`).
Fix: do **not** write `local = g_struct;` — for a whole struct whose size is a
multiple of 16 CW copies it with `lq`/`sq` pairs (8 words, 4 B too long at the top
and every later word shifted), even though the member is `s32 data[8]`. Write the
walk yourself, source pointer declared first (CW gives the *later*-declared pointer
the lower register, and the original has src in `$a2`, dst in `$a1`):

```c
s32 *src;
s32 *dst;
...
src = g_layout.data;
dst = local.data;
i = 4;
do {
    *dst++ = *src++;
    *dst++ = *src++;
    i--;
} while (i > 0);
```
`for (i = 0; i < 4; i++)` does not do it: CW keeps a live `i`, tests with
`slti`+`bnez`, and is 4 B long. `while (--i > 0)` matches but the lint calls it a
double-negate — put `i--;` on its own line inside the body.
Related: the guard above it (`lb $v1,flag; bnez v1 →body; nop / b epi; ld ra /
body…; b back`) came from a positive `if (flag != 0) { body }`, not from
`if (flag == 0) return;` — the then-block goes after the return stub.
