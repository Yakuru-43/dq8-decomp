# New idioms from factory matches

## Saved registers are coloured in REVERSE declaration order
Sign: the diff is `CLASS reorder+register` — size right, every instruction
right, only which `$sN` holds each local differs (twin of a `needs-claude`
function whose note lists its original allocation).

Fix: MWCC's Chaitin colourer removes the saved-register values in numbering
(= declaration) order and colours in the reverse of that, so the
**last-declared** local lands in the lowest free s-register. Read the
original's allocation off the asm and declare the locals in the **reverse**
of it. `notes/idioms.md` "Saved registers follow declaration order" is the
opposite claim: when swapping two declarations doesn't move them, try the
reverse order of the whole group before permuting.

Example: src/SLES_539.74/func_00371260.c — the original had
a=s0, flags=s1, d=s2, c=s3, b=s4; declaring
`s32 v_b; s32 v_c; s32 v_d; s32 flags; s32 v_a;` (reverse) matched at once;
the same C with declaration order (a, flags, d, c, b) gave
a=s0, b=s1, c=s2, d=s3, flags=s4 (score 23).

Solved: func_00371260 2026-11-04 Qwen factory-3; func_0046BEC0 2026-11-04
Qwen factory-6 (locals `n, j, found, good, i` gave i=s0, good=s1, found=s2,
j=s3, n=s4; use-order declaration gave the reverse numbering, score 56)
Likely also: func_00371100 (needs-claude 2026-11-04, identical shape and
allocation; its draft declares a, flags, d, c, b — try b, c, d, flags, a).
