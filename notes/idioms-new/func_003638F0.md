## Plain `beq` with a flag store in its delay slot: the flag is assigned BEFORE the `if`, not inside it
Sign: `beq $v1,$a0,<tag block>; sw $zero,N($sp)` (or `daddu $sN,$zero,$zero`) — a
**non-likely** branch whose delay slot is a store, followed by a test of that same
stack/register slot. Mine (assignment inside the `if` body) gets `beql` with the
next block's argument setup moved into the delay slot, and the store pushed past
the first call inside the block (`sw` lands in a `jal` delay slot 2–3 words later).
The `beq` vs `beql` choice is the tell: CW uses branch-likely only when the delay
slot may be skipped on the not-taken path; a plain `beq` + store means the store
runs on both paths, i.e. the assignment is unconditional in the source.
Fix: write `skip = 0;` before `if (*cur == '<') { ... }`, not as the tag block's
first statement. The loop body is then `skip = 0; if (*c == '<') {...} if (skip ==
0) { copy }` and CW schedules the `sw` into the `beq` delay slot itself.
