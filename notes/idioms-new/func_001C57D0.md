## Two-arm int select whose else arm is one load: write the ternary, not if/else
Sign: a tagged select `if (tag == 1) { v = (s32)f; } else { v = i; }` where both arms are a
single op; drafted as if/else CodeWarrior emits `bnel` + then arm inline + a spurious
`b <join>; nop` after the then arm (mine 8 B too long, CLASS structural, score ~26). The
original falls straight from the last then-arm instruction into the join, and the else load
lives only in the branch's delay slot.
Fix: write the whole select as one ternary: `v = (e->isFloat == 1) ? (s32)e->v.f : e->v.i;`.
CW then folds the else arm into the `bnel` delay slot and drops the back branch. The if/else
form stays right when the else arm is a real block (two-plus ops, its own `b` back) — same
function keeps entries 0 and 4 as if/else and only the gated entry 5 needs the ternary.
