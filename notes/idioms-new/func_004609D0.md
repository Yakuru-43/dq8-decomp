## Loop bound temp in `$a0`: the bound is also the argument of the call right after the loop
Sign: a do-while over a fixed span of the object, `addiu $s0,$s1,K; do { jal f;
daddu $a0,$s0,$zero; addiu $s0,$s0,4; addiu $a0,$s1,E; sltu $v0,$s0,$a0; bnez }`
— the bound `self + E` is recomputed per iteration **in `$a0`** (and `$a0`
survives to the first call after the loop, which then gets a `nop` delay slot
and no arg setup), where plain C colours the bound temp into `$v0` (score 2,
CLASS reorder+register, two words: the `addiu` and its `sltu`).
Fix: the callee after the loop takes that same expression as its argument —
write `func(...); } while (cursor < self + E); tail(self + E);` — CSE makes the
bound one value live across the loop exit into the argument register, and CW
colours it into `$a0` and rematerialises it in the loop body instead of
hoisting. Declare the tail callee with the pointer parameter (check its own
matched src: here `func_00460B90` is `s32 func_00460B90(s32 arg0)`, a wrapper
of `func_283F10`, and the CASINO twin `func_0046B6B0` calls `func_283F10(self
+ 0x568)` directly). If the bound register is wrong, suspect an argument you
dropped from a following call before permuting.
