## `daddu $sN,$v0` in a *later* jal's delay slot: the value is the *previous* call's result
Sign: two calls in a row, `jal A` then `jal B`, and the copy into a callee-saved
register `daddu $sN,$v0,$zero` sits in **B**'s delay slot (mine puts a `nop` there and
copies after B, 4 B too long, CLASS structural). A delay slot executes **before** the
call, so that move reads the v0 that existed *before* B ran — it is A's return value,
kept live in `$v0` by CW's lazy allocation until the last moment, not B's.
Fix: assign the local from the **first** call and let the second be a bare statement:
`handle = func_0046DDF0(); func_0046DE00();` — CW then keeps `handle` in `$v0` and
schedules `daddu $s1,$v0` into the next jal's delay slot by itself. Drafting it as
`func_0046DDF0(); handle = func_0046DE00();` gives `nop` + late copy. General check:
whenever a diff shows `nop` in a delay slot where the original moves `$v0`, ask which
preceding call set `$v0`.
