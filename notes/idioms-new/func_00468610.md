## Two-case switch: CW tests the LAST `case` first; write the arms in reverse of the compare chain
Sign: a small `switch` (no jump table) whose original compare chain tests value B
first (its arm out-of-line after the default) and value A second (`beq` onto the
arm placed inline right after the default's `b <stub>; <delay-slot epilogue load>`).
Writing the source `case B: ... case A: ...` (matching the chain order) makes CW
invert it: A tested first + A's arm inline, and the epilogue layout changes
(mine if/else: score 39 structural; first switch in source/chain order: exact
size but score 39; both arms' dispatch mirrored).
Fix: source order = reverse of the compare chain: `case A: ... case B: ...` —
the arm that is inline in the original (tested LAST) must be written FIRST.
m2c prints the `/* irregular */` switch with the arms in the inline/chain-reverse
order already: trust its listing, don't re-sort the cases into compare order.
