## `daddu $a0,$a1` before the jal where the param also spills to `$sN`: pass a copy
Sign: a parameter is passed to an early `jal` **and** mutated later, so the original has
two copies from `$a1` back to back (`daddu $sN,$a1,$zero` right before the call, then
`daddu $a0,$a1,$zero`), with the `$sN` copy *after* the null-check branch, not woven into
the save/sq region. Writing `digits = callee(value);` with `value` the mutated param
itself hoists `daddu $sN,$a1` into the save region and chains the call arg off the spill
(`daddu $a0,$sN,$zero`) — CLASS reorder+register, score ~7, no local reorder fixes it.
Fix: assign the param to a separate, never-mutated local and pass that:
```c
s32 value;                 /* declared first; n is the param name */
...
if (dst == 0) { return; }
value = n;
written = 0;
digits = func_0022A880(n); /* the callee still sees a1 */
```
CW then copies `a1 -> sN` and `a1 -> a0` as two independent uses, scheduled together
just above the jal. Order the init statements as `value = n; written = 0;` — putting
`written = 0;` first steals the jal's delay slot.
