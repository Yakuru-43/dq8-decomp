# New idioms from factory matches

## `beql $v0,$zero,<epi>; daddu $v0,$sN,$zero`: one trailing return, fail path falls into it
Sign: a call's value is kept in a saved register (`$sN`) by the happy path
and returned by the tail (`b <stub>; daddu $v0,$sN,$zero`), while a fail
path branches **forward** into the epilogue with `daddu $v0,$sN,$zero` in
the branch delay slot — and on that fail path `$sN` was never written: the
original really returns an unassigned local (garbage). Writing the fail
path as an early `return ret;` gives `beqz`/`beqz+nop` **back** to the
shared stub instead, and the `sw`-then-reload of the stored result keeps
the stub alive for all paths.

Fix: use a **positive** nested test for the happy body and let the fail
path fall through to the single trailing `return ret;`; MWCC then tail-
duplicates the epilogue into the branch itself. Also:
- store the call result into the field from `$v0` (`s->f = (T *)f10(...)`),
  then test the **field** (`if (s->f != 0)`) so the reload matches;
- do not initialize the returned local, even though it reads as a bug —
  initializing it emits `li` and changes the stub;
- a `sw` of a constant into a stack local that runs on both arms of the
  following plain `bnez` delay slot must be written as an unconditional
  assignment **before** the `if`, not inside it.

Example: src/SLES_539.74/func_00372D60.c (garbage return),
src/SLES_539.74/func_00372E60.c (single trailing `return 1;` funnels the
early-exit, the store in the plain `bnez` delay slot, and the `b` back from
the tail call).
