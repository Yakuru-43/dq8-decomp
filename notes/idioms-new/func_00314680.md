## Guard clause puts the cold block before the tail: write an explicit `else`
Sign: a null-guard function where the asm has the cold block AFTER the function
tail — success path falls through to a shared `b <epilogue>; ld $ra` stub and the
null block ends with `b <stub>; <pending store in the delay slot>` — while your
guard-clause `if (p == 0) { stores; return; }` compiles to the cold block BEFORE
the tail: the main path gets an extra `b` whose delay slot swallows a store that
the original emits as a normal word (diff: the tail words only, CLASS
structural, low score).
Fix: write the body as `if (p == 0) { cold stores } else { main }` — with an
explicit `else` CodeWarrior lays the main path inline, falls into the single
shared epilogue stub, and places the cold block after it with a `b` back; the
pending store returns to a real word before the stub's `b`.
Example: src/SLES_539.74/func_00314680.c (two calls + four tail stores; the
guard form left `b` before `sw $v0` with the sw in the delay slot).
