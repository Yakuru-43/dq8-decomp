## `mov.s $fS,$f12` in the *first* jal's delay slot + `swc1/lwc1 $fS` save: the function has an f32 parameter, it is not a struct return
Sign: a function whose prologue saves a callee-saved FPR (`swc1 $f20, 0($sp)`, matching
`lwc1` at the epilogue), right after a `jal` it does `mov.s $f20, $f12`, and later passes
`$f12 <- $f20` as the float arg of a *second* call, while `$v0` of the same call goes to an
int local used as the first arg of every call. Drafting the first call as returning a
`{s32; f32}` struct is a dead end: `mwccps2 -O3` returns *every* struct > 4 bytes (mixed,
all-float, union-wrapped — tested A/B/C/D variants) via a hidden pointer in `$a0` + stack
reload, never `(v0, f12)`; the diff shows `addiu $a0, $sp, N` in the delay slot (CLASS
structural, ~240 vs 248 B).
Fix: the float is a parameter of *this* function: declare it `f32 arg2` (after the int
params). CW must copy caller-saved `$f12` into a callee-saved register before the first
call clobbers it, and schedules the `mov.s` into the first jal's delay slot by itself; the
`swc1`/`lwc1` save of `$f20` falls out. The int stays a plain `s32 func_2D34C0();`.
Matched on the 2nd try.
