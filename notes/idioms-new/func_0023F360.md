## Array member address instead of pointer arithmetic: flips which temp gets `$v0`
Sign: an if/switch arm computes a store address from a global and an index as
`lw $v0,%gp_rel(D)($gp); sll $v1,$aN,2; addu $v0,$v0,$v1; sw $r,0xK($v0)`
where the original has the registers the other way round (`lw $v1,<D>;
sll $v0,$aN,2; addu $v0,$v0,$v1`). Rewriting the sum in every operand order
(`D + i*4 + K`, `i*4 + D + K`) and hoisting a named local `off = i*4` (which
instead CSEs the address across arms and shrinks the function) all keep the
global load in `$v0`.
Fix: declare the global as a pointer to a struct with a union-typed array
member at the store offset — `char pad[0x114]; union { s32 i; f32 f; }
entry[];` — and write `D_003E0B24->entry[index].i = v;` / `.f = v;`.
CodeWarrior then materializes the index term into `$v0` and the base load
into `$v1`, matching the original allocation. Two arms with different value
types (one `sw`, one `swc1`) share the member via the union.
