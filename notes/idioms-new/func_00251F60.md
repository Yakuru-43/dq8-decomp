## Pre-guard `x = 0` jumps into the guard's branch delay slot: assign in both arms
Sign: you need a zeroed local on the skip path of a guard (`if (g != 0) { x = f(...); }`
after `x = 0;`), but CW schedules `daddu xreg,$zero,$zero` into the guard's delay slot and
flips it to `beql` (mine: `beql $t0,$zero,+near` + delayed zero, skip block branching
straight to the return stub). The original has a plain `beqz` + `nop` and a cold tail block
`b <join>; daddu xreg,$zero,$zero` that goes through the shared `if (x == 0) return;` test.
Fix: assign explicitly in both arms: `if (g == 0) { x = 0; } else { x = f(...); }`. The true
arm's store stays in its own (cold, tail-laid-out) block and the guard emits `beqz` + nop.
Related: making the scan loop a `static inline` helper with `return`/`return 0;` (see
"inline helpers, and their depth limit") also stopped CW from rotating the body's first
address-computation `sll` into the back-edge delay slot (`bnel`+`sll` -> `bnez`+nop).
