## FP range guard + out-of-line call tail: `const <= x` compare, and the guard as an early return
Sign: two symptoms. (a) An FP range test whose original is `c.le.s $f0,$f1` + `bc1t`
to a shared "flag=0" stub (constant pre-loaded via `lui/mtc1`), where writing
`x >= 20.0f` gives CW the inverted `c.lt.s $f1,$f0` + `bc1f` (DIFF on the branch
opcode, score ~25). (b) The tail `if (arg2 == 1) { jal cold_fn; }`: writing the
outer guard as `if (flag != 0) { switch...; if (arg2 == 1) call(); }` gives an
inverted `bne` over an **inline** call (8 B short, CLASS structural, score 15),
while the original has `beq $a2,$v1` to an **out-of-line** call block that exits
via a shared `b <epi-1>; ld $ra` stub, with the early return landing on its own
lone `ld $ra`.
Fix: (a) write the constant on the left: `if ((20.0f <= x) || (x < 8.0f))` — the
left-constant rule of idioms.md "Constant in a `b` delay slot" holds for FP
compares too (`x < 8.0f` on the right stays as-is: `c.lt.s` + `bc1t`). (b) write
the outer guard as an early return: `if (flag == 0) { return; }` and put the
switch + tail call at top level — CW then lays the call block out of line with
the shared exit stub and the byte-exact tail falls out. Matched on the 3rd try.
Related: BATTLE overlay gp-relative data (`lwc1 N($gp)`) needs the extern
declared `__attribute__((section(".sdata")))` with its name in
`config/symbol_addrs_<bin>_local.txt` (same pattern as the matched
func_0047FC40; a `.data` section attribute compiles to absolute `lui/lwc1`).
