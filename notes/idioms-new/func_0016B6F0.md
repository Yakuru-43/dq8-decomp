## A post-switch null test + read-modify-write tail: write it as a guard clause
Sign: after a switch whose arms produce a pointer in `$a0` (indexed getters,
see `func_0016B2F0.md`), the tail is `beqz $a0, end; nop; lw $v1, 0($a0);
ori; b end; sw $v1, 0($a0); end: jr $ra` — a flag bit ORed in place. Writing
the tail as `if (p != NULL) { *(s32 *)p |= 2; }` keeps every case block right
but gets the join wrong: CW materializes a second copy of the default's
`daddu p, zero` as a stand-alone block at the join entry, points the case
tails' `b` at a `b`-trampoline before it (a `b`-to-`b` chain), and leaves the
store inline with `b end; nop` instead of `b end; sw` (try_match: CLASS
structural, +16 bytes).
Fix: the same semantics as an early return: `if (p == NULL) { return; }
*(s32 *)p |= 2;` — CW then falls the last case straight into the join's
`beqz`, aims the case tails and the fail stubs at it, and schedules the store
into the `b end` delay slot (matched attempt 2 after the change, 240 bytes).
Related to the idioms.md "Guard clauses" entry, which is about duplicated
epilogues, not about the join-entry block here.
