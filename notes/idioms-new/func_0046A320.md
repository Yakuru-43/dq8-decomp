## Argument's second web is rematerialized; a named local holds the saved register
Sign: the original keeps `argN + K` in one `$sX` for the whole body (prologue
`daddu $sX, $aN` in a `jal` delay slot, one `addiu $sX, $sX, K` after it, every
call site uses `daddu $a?, $sX`), where the C spelling either reassigns the
parameter (`arg0 = arg0 + 2;` after the call) or inlines `argN + K` at every
use. Mine then spilled the raw parameter and rematerialized `addiu $a?, $s?, K`
at every call site (CLASS structural, score ~53 on a 7-call body).
Fix: assign `argN + K` to a fresh named local once after the call
(`s32 temp_a1; ... temp_a1 = arg0 + 2;`) and pass that local everywhere.
Locals are numbered with the declarations (before MWCC's generated webs), so
they survive the removal pass and get an `$sX`; a parameter's second web is
numbered last and is rematerialized instead. Related rule: when the body ends
`return C - (call(...) >> 1);`, the original's `sra` into `$v1` + `li $v0` +
`subu $v0, $v0, $v1` tail (vs mine `li $v1` first + `subu $v0, $v1, $v0`) came
from a *single-web* local: `temp_v1 = func(...) >> 1; return C - temp_v1;` —
reassigning the same temp (`temp_v1 = temp_v1 >> 1`) kept the wrong order.
