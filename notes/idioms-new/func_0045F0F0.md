## `sh` then `lh` of the same global before a call: the value stored is WIDER than the global

Sign: the original stores a parameter to a gp/data global (`sh $a2, %gp_rel(D)($gp)`) and
then **reloads** it (`lh $a1, %gp_rel(D)($gp)`) to pass to the next call; your C (`g = arg;
f(&D, g);`) store-forwards and passes `$a2` directly (`daddu $a1,$a2,$zero`), so yours is
one `lui`/reorder off. m2c typed the parameter the same width as the store opcode — wrong:
the parameter is `s32` and the global `s16` (or `u8`/`s8` for `sb`/`lb`). CW cannot forward
a truncated value through a store, so a genuinely narrower global forces the reload.
Fix: type the parameter wider (the wider type is what the store truncation says). No
`volatile`, no temp.
Also in the same function: a `lui $v1,K; sw $v1,%lo(D+K2)($v0)` pair storing a float bit
pattern from a GPR (here `0x3F800000` = 1.0f) is a **u32** write, not an f32 store (an f32
member gives `mtc1`/`swc1`): zero the object with `u128` and write the word through a
`u32 w[4]` in the same union —
`union { u128 q; u32 w[4]; }` with `D.q = 0;` (one `sq $zero`) and `D.w[3] = 0x3F800000;`
(the `+0xC` folds into `%lo(D + 0xC)`, matching the original's second `lui %hi(D + 0xC)`).
