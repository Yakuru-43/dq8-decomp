## Vptr at a MID-object offset: put the 0xC0 data + virtuals in a base class, the tail fields in the derived
Sign: `lw $t9, N($a0); lw $t9, S($t9); jalr $t9` where the object also has fields at
offsets > N+4 (here vptr at 0xC0 but the stores go to 0x130..0x158). One flat struct
with `u8 pad0[0xC0]; ...virtuals...; f32 f_130;` puts the vptr at the END of all data
(0x158 here), so the `lw $t9` reads the wrong offset — the DIFF is the vptr load plus
every store shifted by (vptrPos - N).
Fix: a `.cpp` with `struct Base { u8 pad0[N]; virtual ...; };` (CW puts the vptr right
after the base's own data, at N) and `struct Unit : Base { u8 padAfterVptr[...] ; the
fields past N+4 };`. Declare the virtuals in slot order: slot S is the (S-8)/4+1-th
virtual (0x48 = 17th; pad the list with `virtual s32 vK();` stubs — declarations, no
bodies, no link error). Call through the derived pointer: `unit->GetMat();`.
