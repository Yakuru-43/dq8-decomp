## Allocator-handle field as `void *` keeps the guard-and-call block inline
Sign: a function guards a call `h(obj->ctx, obj->field)` with `if (obj->ctx != 0 && obj->field != 0)`
after an early `if (obj->ctx == 0) return;`. Declaring the ctx field `s32`, CW inverts that guard:
it tests the second operand inline and moves the ctx test (+`lw $a0`) out-of-line near the epilogue
with a `b` back, 16 B too long; nesting the ifs keeps the wrong test inline (nop delay slot).
Fix: declare the handle `void *f4;` and the callee `(void *, void *)`. With the pointer type CW
emits the original `lw $a0; beqz $a0; lw $a1(delay); beqz $a1; nop; jal; nop` chain, and to get the
arg load into the first `beqz` delay slot assign both operands to named locals before the `if`.

## Compare operands the other way round when CW won't reuse the base register
Sign: `if (p != 0 && p->f0 == obj->g0)` needs `lw $v0,0($v0); lw $v1,0($sN)` (deref overwrites the
base register) but CW emits `lw $v1,0($v0); lw $v0,0($sN)` — a 2-word register-only diff a permuter
run can't reach (permute.py needs `cpp`, absent here). No type change fixes it.
Fix: take the pointer into a local (`tag = board->f1930;`) and flip the compare:
`if (node->f0 == tag->f0)`. The right-to-left operand order lets CW clobber the base reg with the
deref; load order in the stream stays as the original.
