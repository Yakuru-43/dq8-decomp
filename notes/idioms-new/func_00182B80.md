## Array slot cached in a local CSEs stores the original reloads: re-read the global
Sign: a loop over a global pointer array (`for (i...) ... D_0040F9D0[i] ...`)
whose original reloads the slot (`lw v1, 0(a2)`) before every store in the body,
the first access alone using the guard's register. Caching `e = D_xxx[i]` in a
local reuses one register for all accesses — missing `lw`s, arm tails shifted,
CLASS structural.
Fix: don't cache: write each access as `D_xxx[i]->field = ...`. CodeWarrior does
not CSE a `.data` load across stores (a store may change the array) but always
CSEs a local pointer variable. Guard loads before any store still fold to one
`lw` (no store between them). Try this before the inline-member-accessor fix in
notes/idioms.md: that one is for struct fields behind a register, not globals.
