## Positive-test if/else with a cold else keeps plain `beqz` + `nop`

Sign: you need `beqz $rX, <late block>; nop` on a *loaded pointer* test,
where the late block ends with `b <join>` and its first load wants to sit
in a delay slot — but writing the null arm first
(`if (p == 0) { cold } else { main }`, or guard-first `if (p == 0) { cold; }`
then the main path) makes CodeWarrior emit `beql` and hoist the cold
block's load into the delay slot (function comes out 1 word short;
CLASS reorder+register on an otherwise-perfect diff).

Fix: write the **positive** test with the main path as the if-arm and the
cold arm as the trailing `else`:
```c
if (key != 0) {
    id = key->id;
    if (...) { return; }          /* guards stay in the if-arm */
    ...
} else {
    id = *obj->def;               /* laid out cold at the tail, b back */
}
```
The join after the if/else stays single. Do not "simplify" to an early
`return` in the else — the `b` back to the join is the point. Distinct
from SKILL's branch-likely null check (call results tested as integers)
and from the `beqz p` falls-into-`p != 0` entry in notes/idioms.md:
here the same pointer test flips between beql-with-hoist and beqz+nop
purely on arm order.
