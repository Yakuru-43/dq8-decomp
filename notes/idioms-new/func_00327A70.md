## Two address `addu`s emit base-first where the original is index-first: a typed struct member array

Sign: score 1–2, CLASS reorder+register, only `addu $v0,$v0,$aN` where the original is
`addu $v0,$aN,$v0` (twice, once per scaled term). The draft adds byte offsets as int
arithmetic: `v = *(f32 *)(base + row * 28 + i * 4 + 0x40)`. Every reorder of that
expression (attempts 2–4: swap operands, split statements, temp locals) fixes one addu
and flips the other; never both.

Fix: the original's address comes from a **member array at a constant offset in a
struct**, indexed by a computed subscript (`MH2 Index → "addu operands the other way
round"`, Addresses section: a subscript with a constant offset puts the scaled index
first). Give the base the type instead of casting it inside the load:

```c
struct Stats { u8 pad[0x40]; f32 vals[2][7]; };
struct Stats *tbl = (struct Stats *)func_00342840();   /* s32 getter */
v = tbl->vals[mode == 0][i];                           /* two index-first addu, 0x40 stays in lwc1 */
```

Both scaled terms (`vals` row * 28, index * 4) then emit index-first, the constant
offset stays in the `lwc1` displacement, and the bool subscript keeps its
`xor`+`sltiu` normalization — all matched first try of that shape.
