## Mixed lvalue forms: stores via `M2C_FIELD(&local, s8 *, N)`, plain member reads

Sign: a local struct whose byte member is stored several times: the original
materializes the field address once (`addiu $a3,$sp,0xC`) and every `sb` goes
through `0($a3)`, but later plain loads of the same field are sp-relative
(`lb $v1,0xC($sp)`). One `s8 *t = &local.type` pointer used for BOTH reads and
stores gives every load through `$a3` too (diff: `lb $v1,0x0($a3)` vs
`lb $v1,0xC($sp)`); plain member access everywhere drops `addiu $a3` entirely.

Fix: write the STORES as `M2C_FIELD(&local, s8 *, N) = x;` and the READS as
`local.field` (or `*(&local.field)` never — the plain form). CW CSEs the repeated
`(char *)&local + N` casts into the `$a3` base for the byte stores, but does not
link them to the member's value slots, so reads stay sp-relative — exactly the
original's mix. Pair it with named locals for values read in two arms
(`s32 lval = left->v.i;` before the inner `if`s) so the load is hoisted into the
guard branch's delay slot and shared between arms.

Example: `src/SLES_539.74/func_00356D00.c` (Val tagged-union add: `temp` copy of
`right`, tag RMWs through `M2C_FIELD`, `result->type = temp.type` tail).
